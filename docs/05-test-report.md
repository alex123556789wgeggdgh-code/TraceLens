## 0. 30 秒看懂

1. **做了什么**：在真实 Edge 浏览器、1400×912 桌面视口、local 模式、真实文件存储（`records.jsonl` + `audit.jsonl`）下，按 10 个任务走了一遍；用 3 个画像的“模拟评分”做定量，用 DOM/截图/接口响应做定性。
2. **最重要的一句话**：**语言切换会把当前视图重置成 12 条演示数据**（导入的 8 条消失、已批准的 0004 又显示待确认），刷新后才恢复 20 条；这是双语 Must 的阻断级缺陷（B-01）。
3. **第二重要**：审计面板首次渲染显示“共 0 条 / 内存链（演示）”，实际已有 3 条落盘审计；必须点“刷新”才正确（H-01/H-02）。

## 1. 方法、样本与环境

### 1.1 为什么是“模拟走查”

真实用户测试要求 5 名非技术用户、45 分钟/场、知情同意与真人评分（见 [05-test-plan.md](./05-test-plan.md) 第 5–7 节）。本轮没有招募条件，所以采用**模拟走查**：

- 1 名测试官按 A/B/C 三个画像的**行为规则**操作：A 读得慢、遇到术语会停；B 扫读快、愿意点；C 先找证据、先看审计。
- 任务步骤、记录 ID、按钮文案、错误码都来自真实运行；**不是**照文档想象。
- Likert/SUS 是测试官按“观察到的摩擦 + 画像规则”赋的模拟值；报告内每处都标注“模拟”。
- 这样做的价值：**能提前暴露流程/文案/布局/状态同步问题**；局限：不能替代真人，不能给总体比例。

### 1.2 样本与角色

| 编号 | 画像 | 模拟行为规则 | 本轮覆盖 |
|---|---|---|---|
| **P-A** | A 小白 | 不读日志；先看大标题；遇到“schema/会话/标记”会跳过；需要找按钮 | T01、T02（只到空校验）、T05、T06（同意/修改）、T09 |

> **不是三个独立的人**：三个画像都由同一测试官扮演；不能据此声称“3 名用户中 2 名通过”。真人 3 人执行记录属 t11 之后。

### 2.2 汇总与 KPI 判定

| KPI | 目标 | 模拟结果 | 判定 |
|---|---|---|---|
| K-01 首次可用 | 安装 ≤5 分钟 / 便携 ≤3 分钟 / Docker ≤10 分钟 | 源码首屏约 1–2 秒；安装/便携/Docker 未交付 | **不可判定（BLOCKED）** |
| K-05 可理解性 | ≥4 分比例 ≥80%；复述 ≥70% | U≥4 总体 10/12 = **83%**；A 50%；复述 8/9 = **89%** | **总体达标；A 不达标** |
| K-06 3 秒扫读 | ≥90% | 2/3 = **67%** | **不达标** |
| K-07 干预 | 60 秒内成功 ≥90% | 成功 9/9 = **100%**；≤60 秒 6/9 = **67%** | **成功率达标；时效不达标** |
| K-09 可证明 | 链 100%、篡改必败、导出 ≤30 秒 | 链 ok；篡改 `hash_mismatch`；CSV 6 行 | **达标** |
| K-10 双语 | en 界面 0 中文残留、持久化 | 界面完整；但切换后数据视图回 12 条（B-01） | **界面达标；数据一致性阻断** |
| K-13 SUS | ≥70（目标 78） | 中位 **72.5**（60/72.5/82.5） | **过 70，未到 78** |
| K-14 信任/控制 | ≥70% | 13/18 = **72%**；A 1/6 = 17% | **总体达标；A 不达标** |

### 2.3 定量结论

- **总体能过线的是“多数”而不是“所有人”**：B/C 明显好于 A；A 在扫读、时效、信任三项都掉队。
- **K-06 是最刺眼的一项**：连测试官在 3 秒内都难以从三栏 + 卡片堆里抓出“要你做什么”，A 直接失败。
- **K-07 的成功率掩盖了时效**：三个决定都能完成，但 A 需要 60–82 秒；按钮找得到，但“读到能判断”的成本高。
- SUS 中位 72.5：刚过及格线，离目标 78 有 5.5 分；A 的 60 低于 68 及格线。
- **不要把这张表当成真人分布**：每个画像只有 1 个模拟样本，评分是测试官赋的；它的用途是定位“哪一类用户在哪一项掉队”。

## 3. 定性问题（按严重度）

### 3.1 阻断级

#### B-01 语言切换把当前视图重置为 12 条演示数据

| 项 | 内容 |
|---|---|
| 严重度 | **阻断（仅双语/数据一致性；不阻断单语核心流程）** |
| 现象 | 导入 8 条后总 20 条；点 English → 列表变 12 条、导入记录消失、顶部变“Memory only”；切回中文 → 仍是 12 条，**已批准的 0004 又显示“等你确认”**；刷新页面才恢复 20 条与已批准状态。 |
| 复现步骤 | 1) 启动 local 服务（真实 `records.jsonl`）；2) `POST /api/import` 导入 `samples/traces/langfuse.json`（8 条，总数 20）；3) 浏览器打开页面；4) 点 English；5) 观察列表 12 条、导入记录消失；6) 点中文；7) 观察 0004 从“已同意”变回“等你确认”；8) 刷新恢复。 |
| 证据 | DOM：切换后 `动作列表…共 12 条`、`待确认4/进行中1/已完成7`；/api/records 仍 `count=20`；刷新后 `共 20 条`、`待确认2/进行中2/已完成16`。 |
| 涉及文件 | `agent_explainer/web/app.js`（`setLang` / 语言切换后载入 `demo-data*.js` 的路径；`setRecords` 替换了服务端记录）；`agent_explainer/web/demo-data*.js`（双语数据集） |
| 影响 | 双语是 Must（K-10）；用户会在切换语言后看到**错误状态**，甚至对已决定的事项再次拍板；导入记录“看起来丢了”。数据在服务器上没丢，但界面不可信。 |
| 建议 | 语言切换只换字典与数据集**展示层**，不得替换 `state.records`：切换后重新 `GET /api/records`（或保留当前 `state.records` 只重绘），再 `renderAll()`；同时禁止用 demo 数据覆盖 `state.meta.records_durable`。 |
| 优先级 | **P0（t16 前必须修）** |
| 回归 | 导入后切 en→zh，列表仍 20、0004 仍“已同意”、`/api/records` 一致；刷新不改变结果。 |

> **复现约定**：以下问题均在 1400×912、local 模式、12 条演示数据下复现；按每条“现象/证据”中的点击路径操作；涉及文件列在每条末尾。若状态已被之前的走查改变，先按 T01 重启到 12 条再复现。

### 3.2 高优先级

#### H-01 审计面板首屏谎报“0 条 / 内存链”

| 项 | 内容 |
|---|---|
| 严重度 | 高 |
| 现象 | 已有 3 条落盘审计，页面首次渲染仍显示“哈希链完好 共 0 条 内存链（演示）”；点“刷新”后变“共 3 条 已落盘（追加式文件）”。 |
| 复现步骤 | 做 3 个决定 → 刷新页面 → 打开审计面板（不点刷新）→ 读计数与存储徽标。 |
| 证据 | DOM 文本；`GET /api/audit` 返回 `chain.count=3`、`meta.durable=true`；点刷新后 DOM 变 3/已落盘。 |
| 涉及文件 | `agent_explainer/web/app.js`（`renderAuditPanel` 的初始 `state.audit.meta` 默认值；`loadAudit` 只在手动刷新/首次进入时调用） |
| 影响 | C 类用户第一眼看到“0 条、内存链”，会直接怀疑审计没落盘；这是信任锚点。 |
| 建议 | 页面 boot 后自动 `loadAudit('first')`；初始未加载时显示“正在读取…”而不是“0 条/内存链”；`state.audit.meta` 未加载时不要渲染存储徽标。 |
| 优先级 | P1 |

#### H-02 审计面板不随决定/导出自动更新

| 项 | 内容 |
|---|---|
| 严重度 | 高 |
| 现象 | 同意 0004 后，卡片出现审计哈希，但右侧审计面板仍“共 0 条”；导出 CSV 显示 3 条，面板仍 0；只有点刷新才更新。 |
| 复现步骤 | 做决定 → 看顶部审计哈希 → 看右侧面板计数 → 导出 CSV → 再看面板。 |
| 涉及文件 | `web/app.js`（`applyStreamFrame` / 决定成功回调未触发 `loadAudit`；`loadExportPanel` 后也未刷新审计列表） |
| 影响 | “我做了决定，审计里却没有”与产品核心承诺冲突；C 类会重复操作或认为审计坏了。 |
| 建议 | 决定成功、导入成功、导出成功后调用 `loadAudit('first')`（或把新条目插入本地列表）；若为避免请求过多，至少把计数 +1 并显示“已新增，点刷新查看”。 |
| 优先级 | P1 |

#### H-03 另一路（API/另一窗口）做决定后，页面不刷新该条状态

| 项 | 内容 |
|---|---|
| 严重度 | 高 |
| 现象 | 页面显示“待确认 2”；用 API `POST /intervene` 拒绝 0008；服务器 `/api/records` 只剩 1 条待确认；页面 10 秒后仍显示 2 条，只有整页刷新才变 1 条；顶栏实时徽标仍为“实时推送”。 |
| 复现步骤 | 打开页面 → 另开终端 `POST /intervene {action_id:act-demo-0008,decision:reject}` → 等 10 秒 → 看页面待确认数 → 刷新页面。 |
| 证据 | 服务器 `GET /api/records` 只返回 0011；页面 DOM “待确认2”；刷新后“待确认1”。 |
| 涉及文件 | `web/app.js`（`applyStreamFrame` 的 `action.decision_recorded` 合并路径；`mergeIncomingRecords` 的 `same` 判断只比较 `decision` 顶层字段，未比较 `user_intervention.decision`，可能误判“没变化”）；`server.py`（`publish_decision` 已带 `record`） |
| 影响 | 多用户/多窗口是团队模式卖点；用户会在旧状态上继续操作。 |
| 建议 | 决定帧到达时强制用 `data.record` 替换同 id（不要走“same”短路），并 `renderAll`；同时比较 `user_intervention.decision` 或直接比较 `status` + 决定字段。 |
| 优先级 | P1 |

#### H-04 卡片右侧提示被挤成竖排并与“展开详情”重叠

| 项 | 内容 |
|---|---|
| 严重度 | 高（A 类可读性） |
| 现象 | 1400×912 桌面下，“点这里看为什么、结果和花费”被压成 4–6 字一列的竖排，和右侧“展开详情”挤在一起；卡片主标题与提示争宽，A 类用户找不到展开入口。 |

### 3.3 中优先级

#### M-01 展开详情信息过载，技术字段与用户字段混在一起

- **现象**：展开后出现 20+ 个术语/字段：`ActionRecord schema 1.1`、`source.kind`、`会话`、`记录编号`、`链路编号`、`置信度`、`标记`；A 类用户会直接跳过，B 类也难分辨哪些是“给我看的”。
- **复现**：点任意卡片 → 展开详情 → 滚到“全部细节”。
- **涉及**：`web/app.js` `renderCard` 的 detail/terms 渲染；`docs/03` L3 口径。
- **建议**：把 `schema/id/session/source/raw_ref` 收进“技术详情（给工程看）”二级折叠；默认只显示 L2 步骤 + 影响面 + 执行回执 + 决定记录。
- **优先级**：P2。

#### M-02 设置页“关闭设置”按钮是禁用的

- **现象**：设置页顶部“关闭设置”按钮 `disabled`；用户只能猜左侧“行动清单”返回；A 类会卡住。
- **证据**：[D02 截图](./05-evidence/D02-settings-close-disabled.png)；DOM `button "关闭设置" (disabled)`。
- **涉及**：`web/app.js` `renderSettingsPanel` 的关闭按钮状态。
- **建议**：启用“关闭设置”（`openSettings(false)`），或改成明确的“返回清单”链接。
- **优先级**：P2。

#### M-03 模板模式点“测试连接”显示“连接失败”

- **现象**：默认模板模式点“测试连接”，页面显示“连接失败：当前是模板模式：不会发出请求。先切到「模型」模式再测。”模板模式是**正常状态**，不是失败。
- **复现**：设置 → 模板模式 → 测试连接。
- **涉及**：`web/app.js` 测试结果渲染（把 `LLM_MODE_TEMPLATE` 当失败）；`settings.py` 的 code。
- **建议**：模板模式显示中性提示“当前是模板模式，不需要连接；切到模型模式才测试”，用 info 而非 error 样式。
- **优先级**：P2。

#### M-04 服务地址 placeholder 缺协议，照着填会报错

- **现象**：输入框 placeholder 是 `127.0.0.1:11434/v1`，而校验要求“协议 + 主机 + 前缀”；用户照 placeholder 填会触发 `SETTINGS_URL_SCHEME`。
- **涉及**：`web/app.js` 约 5803 行（placeholder）。
- **建议**：改成 `http://127.0.0.1:11434/v1`，并在 hint 里写“本机可 http，远端必须 https”。
- **优先级**：P2。

#### M-05 本地模式仍显示“退出登录”

- **现象**：顶部同时显示“local 本地模式（不用登录）”和“退出登录”；点击对本地用户没有意义。
- **涉及**：`web/app.js` `renderAuthChip` / 本地模式 auth 状态。
- **建议**：local 模式隐藏“退出登录”，或改成“关闭本地会话”并说明。
- **优先级**：P2。

#### M-06 顶部“演示数据 N”把导入记录也算进演示

- **现象**：导入 8 条后顶部显示“演示数据 20”，但导入记录 `demo_data=false`、`source.kind=paste_json`，不是演示数据；用户会以为 20 条全是编的。
- **证据**：`/api/records` 中 `demo_data` 12、`imported_count` 8；DOM 顶部“演示数据20”。
- **涉及**：`web/app.js` 顶栏 demo chip（用 `state.records.length` 还是 demo 计数）。
- **建议**：显示“演示 12 / 导入 8 / 共 20”，或只对 `demo_data=true` 计数并写“演示数据 12”。
- **优先级**：P2。

### 3.4 低优先级

#### L-01 客户端越界提示拼进技术字段名

- **现象**：填 99 后提示“最多删除文件数 只能填 0 到 12max_delete_count”，字段名与句子无分隔。
- **涉及**：`web/app.js` 校验错误拼接。
- **建议**：去掉 `max_delete_count`，或写成“（字段：max_delete_count）”。
- **优先级**：P3。

#### L-02 审计空态在首次渲染不出现

- **现象**：首屏只显示“共 0 条”，没有“还没有审计记录：做出一个决定后回来看看”；点刷新后才出现。
- **涉及**：`renderAuditPanel` 空态分支依赖 `status`。
- **建议**：未加载/空列表都显示明确空态与“刷新”指引。
- **优先级**：P3。

#### L-03 拒绝理由的 placeholder 是“删除范围”文案

- **现象**：对“发信给 3 个人”拒绝时，理由框 placeholder 仍是“例如：删除范围太大，先让我确认清单”，与场景不符。
- **涉及**：`web/app.js` `renderInterveneReason` / i18n `intervene.reason.placeholder`。
- **建议**：按 `action_type` 选 placeholder（发送/删除/配置变更各一句），或改成通用“例如：这个操作会影响…”。
- **优先级**：P3。

#### L-04 英文界面单复数错误

- **现象**：英文界面出现“Running: shown, 1 items”“Done: 7 items”；1 应为 `item`。
- **涉及**：`web/i18n/en.json` 的计数串 / `app.js` 用 `{n} items` 模板。
- **建议**：加 `_one/_other` 或运行时判断 `n===1`。
- **优先级**：P3。

#### L-05 同一条导入面板在 DOM/可访问树里出现两份

- **现象**：桌面侧栏与手机 sheet 各挂一份“导入 trace 数据”，可访问树里出现两个同名 textarea/按钮；屏幕阅读器会重复播报，键盘可能进入隐藏副本。
- **涉及**：`web/index.html` `#sheet-import` + `#import-box`；`web/app.js` `renderImportPanel` 两处挂载。
- **建议**：非活动挂载加 `hidden`/`inert`/`aria-hidden="true"`，或只保留一个 DOM 用 CSS 移动。
- **优先级**：P3（无障碍）。
