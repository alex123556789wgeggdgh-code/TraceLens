## 4. 构建

```bash
cd agent-explainer

# 构建（默认装 reportlab，审计导出能真出 PDF）
./scripts/docker-build.sh

# 构建 + 导出离线镜像 tar（release/<版本>/tracelens-<版本>-image.tar + SHA256SUMS.txt）
./scripts/docker-build.sh --save

# 等价的手写命令
docker build --build-arg TRACELENS_VERSION=0.4.5 -t tracelens:0.4.5 -t tracelens:latest .
```

**两阶段各干什么**（不是摆样子，每一步都能让构建当场失败）：

| 阶段 | 内容 | 落进运行镜像的产物 |
| --- | --- | --- |
| `builder`（`python:3.12-slim`） | 只拷 `agent_explainer/` 与 `samples/`；`python -m compileall` 做**语法闸门**并生成字节码；`pip install --target=/opt/deps reportlab`（可关） | 源码树 + `__pycache__` + `/opt/deps`（仅这两个目录被 COPY） |
| `runtime`（`python:3.12-slim`） | 建 `tracelens` 用户（uid/gid **10001**，无登录 shell）、拷产物与两个运维脚本、建 `/app/var` `/app/logs` 并 chown、`HEALTHCHECK`、`USER 10001:10001` | 交付镜像（gcc/pip 缓存/构建工具链一个都不在） |

构建参数：

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `TRACELENS_VERSION` | `0.4.5`（取自 `server.SERVER_VERSION`） | 写进 `LABEL org.opencontainers.image.version` 与镜像标签；`/health` 上报的是同一个号 |
| `TRACELENS_WITH_PDF` | `1` | `1` 装 reportlab（导出真出 PDF）；`0` 不装（导出**自动回退**可打印 HTML，4.8 已实现的降级路径，本机实测见 §11） |

**实测数字**（最终这次，`release/0.4.5/`）：

| 项 | 值 |
| --- | --- |
| 镜像 ID | `sha256:51d5b69752ce2d89a581c6066cd593fe6716a448b0ca499f2bcd61d912b0b4b1` |
| 镜像体积 | 243,566,055 字节（232.3 MiB） |
| 构建耗时 | 热缓存 **3s**；首次（含 `python:3.12-slim` 拉取 4.0s + reportlab 安装 2.5s）**10.2s** |
| 离线 tar | `release/0.4.5/tracelens-0.4.5-image.tar`，63,299,584 字节（60.4 MiB），sha256 `6a738832c7d2632f741ff2d1da7b469fdc63e91162e1df839b1099c280e2170d` |

> 镜像 ID 每次构建都会变（`Created` 时间戳被烘进 config），体积与层内容不变。
> 交付以 `IMAGE-INFO.json` + `SHA256SUMS.txt` 为准，别手抄 ID。

## 5. 用 Compose 起团队服务器（推荐）

```bash
cd agent-explainer

cp scripts/env.example .env        # ① 复制环境变量样例
# ② 编辑 .env：至少把 TRACELENS_ADMIN_PASSWORD 换成真口令（≥10 位，别用 password/tracelens 这类）
docker compose up -d               # ③ 构建（若无镜像）+ 起容器
docker compose ps                  # 等 STATUS 变 healthy（start_period 15s，interval 30s）
curl -s http://127.0.0.1:8765/health   # 200 且 "status": "ok"
```

浏览器打开 `http://127.0.0.1:8765/`（同事用 `http://<这台机器的 IP>:8765/`），用 `admin` + `.env` 里的口令登录。
首次登录产品会要求改密（`must_change_password=true`，安全设计，不是故障）。

compose 里的关键项（全部可改）：

| 项 | 值 | 为什么 |
| --- | --- | --- |
| `ports` | `${TRACELENS_PORT:-8765}:8765` | 容器内固定 8765；宿主端口可换 |
| `volumes` | `./data:/app/var`、`./logs:/app/logs` | 宿主目录**绑定挂载**（不是匿名卷）：备份=拷目录，升级=换镜像不换目录 |
| `restart` | `unless-stopped` | 机器重启/进程崩了自动拉起；人手动 `stop` 之后不再自己起 |
| `user` | `10001:10001` | 与镜像 `USER` 一致，非 root 运行（`docker compose config` 里一眼可见） |
| `init` | `true` | tini 当 PID 1，入口包装里的 `tee` 子进程能被正确回收，`SIGTERM` 干净退出 |
| `healthcheck` | `python /usr/local/bin/tracelens-healthcheck.py`（interval 30s / timeout 5s / retries 3 / start_period 15s） | 真发 `/health` 判 200+`status=ok`，不是"端口通就算健康" |
| `logging` | `json-file`，`max-size=10m`、`max-file=3` | 防止长期运行把宿主磁盘写满 |
| `security_opt` | `no-new-privileges:true` | 容器内不能提权 |
| `tmpfs` | `/tmp` | 非 root 也能写临时目录，且不落宿主磁盘 |
| `environment` | 见下表 | 只显式注入这些，不把宿主 shell 整包塞进容器 |

容器里能拿到的环境变量就这些（`.env` 只做 compose 变量插值，其余宿主变量不会漏进容器）：

| 环境变量 | 必填 | 默认 | 说明 |
| --- | --- | --- | --- |
| `TRACELENS_ADMIN_PASSWORD` | ✅ | 无（**缺了 compose 直接报错停下**） | team 模式零用户时用它建 `admin`；首次登录强制改密 |
| `TRACELENS_DEMO` | — | `zh` | 首启种子：`zh` 中文演示 12 条 / `en` 英文 12 条 / `none` 从 0 条开始 |
| `TRACELENS_PORT` | — | `8765` | 宿主端口 |
| `TRACELENS_UI_LANGUAGE` | — | `zh` | 界面语言（`zh`/`en`） |
| `TRACELENS_LLM_MODE` | — | `template` | `template`＝纯离线模板（功能不缺）；`llm` 才调模型 |
| `TRACELENS_LLM_PROVIDER` | — | 空 | `openai_compat` / `ollama` / `deepseek` / `custom` |
| `TRACELENS_LLM_BASE_URL` | — | 空 | 非回环地址必须 `https` 且显式放行出网 |
| `TRACELENS_LLM_MODEL` | — | 空 | 模型名 |
| `TRACELENS_LLM_API_KEY` | — | 空 | 密钥只走环境变量，**team/容器模式不落盘** |
| `TRACELENS_LLM_ALLOW_OUTBOUND` | — | `0` | 非回环主机必须置 `1`，否则 403 `LLM_OUTBOUND_BLOCKED` |
| `TRACELENS_LLM_TIMEOUT_S` | — | `30` | 模型调用超时（0.5–120） |

**首次管理员口令的三种情形**（实测口径）：

| 情形 | 行为 | 你要做什么 |
| --- | --- | --- |
| `.env`/环境变量给了 `TRACELENS_ADMIN_PASSWORD` | 首启用它建 `admin`，控制台打印"初始口令来自环境变量 TRACELENS_ADMIN_PASSWORD"；`must_change_password=true` | 用它登录，然后按界面提示改密（改完 `.env` 里那条就只是下次重建空库时的初始值） |
| 没给（只用 `docker run`，或 compose 被绕过） | 产品**生成一次性口令**，只打印到控制台（也就是 `docker logs` 与 `./logs/tracelens-*.log`），任何 HTTP 接口都拿不到 | 立刻 `docker logs tracelens \| grep 初始口令` 取走并登录，然后改密；由于口令进了日志，文件的权限是 0600 |
| 数据卷里已经有用户（不是首启） | **不**再创建 admin，沿用卷里的用户表 | 用已有账号登录；口令忘了见 §12 第 4 问 |

## 6. 不用 Compose：纯 `docker run`

```bash
./scripts/docker-run.sh                 # 起在 8765，数据落 ./data ./logs，起完自动等 /health

# 等价手写命令（注意 -v 用绝对路径）
mkdir -p data logs
docker run -d --name tracelens -p 8765:8765 \
  -v "$PWD/data:/app/var" -v "$PWD/logs:/app/logs" \
  -e TRACELENS_ADMIN_PASSWORD='你的口令（≥10 位）' \
  --entrypoint /usr/local/bin/tracelens-entrypoint \
  --restart unless-stopped --security-opt no-new-privileges --tmpfs /tmp \
  tracelens:0.4.5 \
  python -m agent_explainer --mode team --host 0.0.0.0 --port 8765 \
    --demo zh --data-dir /app/var
```

想用**镜像自带入口**（与任务规格逐字一致、不做日志 tee）就去掉 `--entrypoint` 那一段：

```bash
docker run -d --name tracelens -p 8765:8765 \
  -v "$PWD/data:/app/var" tracelens:0.4.5          # ENTRYPOINT 里的 --mode team --port 8765 全部生效
```

## 7. 数据卷：里面有什么、怎么备份/恢复

`./data`（容器内 `/app/var`）是**唯一的持久化位置**，用户全量数据都在这里：

| 文件 | 内容 | 能删吗 |
| --- | --- | --- |
| `records.jsonl` | 记录日志（4.9 追加式 JSONL + 内存索引；坏行跳过并封口） | 删了=清空所有行动记录（审计仍在，但引用会悬空） |
| `audit.jsonl` | 审计链（append-only，链头 `sha256` 逐条串起来） | **不能删不能改**：改一字节链就断，`/health` 的 `audit.ok` 变 `false`、`/api/audit` 直接 500 |
| `settings.json` | 设置（team 模式密钥不落盘，只有 `api_key_present/mask/fingerprint`） | 删了=回到出厂设置 |
| `auth/auth-state.json` | 用户表 + 会话（只禁用不删除；口令是 `pbkdf2_sha256` 摘要） | 删了=所有账号没了，重启会重新 bootstrap 一个 admin（见 §12 第 4 问，实测记录不受影响） |
| `ingest/tokens.json` | 上报令牌（落盘只有 `sha256(salt+明文)` + 前缀，`chmod 0600`） | 删了=所有 webhook 令牌失效 |
| `features/secretariat/identities.jsonl` | **5.0 总裁办**：哈希链身份账本（`seq`/`prev_hash`/`entry_hash`，创世全零） | **不能删不能改**：删了=Agent 身份与签名链全没，历史签名的认定书验不过 |
| `features/secretariat/{delegations,letters}.jsonl` | 5.0 委托链与认定书（同为哈希链） | 同上，删了链条断 |
| `features/secretariat/keyring.json` | 5.0 密钥库（`ed25519` 私钥，容器内 `-rw-------`，状态里 `keyring.mode=0o600`） | **删了=私钥没了**：旧签名无法再验证，新记录签不出来 |
| `features/evidence/`、`features/rollback/` | 证据文件与回滚快照 | 删了=对应证据/回滚点丢失 |
| `records.jsonl.lock` | 跨进程文件锁（0 字节） | 容器停着时可以删，运行中别动 |

**5.0 总裁办账本落在哪（实测，不是推测）**：`--features` 的默认值是
**`<应用根>/var/features`**，它**不跟随 `--data-dir`**（桌面便携版就栽在这条默认值上，
把账本写进了只读的包内目录，见 `docs/audit/v050-sidecar.md`）。容器里应用根 = `/app`、
绑定挂载 = `/app/var`，所以默认落点 = `/app/var/features` = 宿主 `./data/features`，
本来就在卷内；`docker-compose.yml` 与 `scripts/docker-run.sh` 现在**显式**传
`--features /app/var/features`，让这条不变量与 `WORKDIR`、`--data-dir` 的取值无关——
升级换镜像（§8）时账本与私钥跟着卷走，不被镜像冲掉。实测证据（本机 source 模式，
命令口径与容器 command 一致）：登记身份后 `identities.jsonl`(547 B) + `keyring.json`(336 B)
在指定目录里，停进程（=删容器）再重启（=卷保留）后 `counts.identities` 不减、
`chains.identities.ok=true`、链头非创世全零。见 `docs/audit/v050-docker.md` §4。

> 鉴权口径：team 模式下 `/api/secretariat/*` **需要登录**——未登录
> `GET /api/secretariat/status` 是 `401 AUTH_REQUIRED`（`local` 模式才公开）。
> 验收/巡检脚本要先 `POST /api/auth/login` 拿会话，再带 Cookie + `X-CSRF-Token`
> （写请求的 CSRF 令牌就在登录响应里）。

`./logs`（容器内 `/app/logs`）：入口包装把 stdout/stderr 用 `tee` 同时落成
`tracelens-YYYYMMDD.log`（首启抬头写 uid、数据目录、完整 argv）。
容器内实测：该文件是 `-rw-------`（umask 077，只有 uid 10001 能读），
`/app/var` 里的 `records.jsonl` / `audit.jsonl` 同样是 `-rw-------`（store/audit 自己钉的 0600）。
Windows Docker Desktop 的绑定挂载在**宿主侧**看不到这些 POSIX 权限（模拟成 644/777），容器内看到的是真的 0600。
镜像自带的默认 `ENTRYPOINT` 不做 tee（保持规格原样），那时只能看 `docker logs`。
**注意**：这份日志里可能出现一次性管理员口令（见 §5），文件按 0600 建，别随手贴到工单里。

备份（容器可以不停，`records.jsonl` 是追加写）：

```bash
# 最稳：先停容器再拷（停 2 秒，写完的都已落盘）
docker compose stop
tar czf "tracelens-data-$(date +%Y%m%d-%H%M).tar.gz" data logs
docker compose start
```

恢复：

```bash
docker compose down
mv data data.broken            # 先留证据，别直接删
tar xzf tracelens-data-YYYYMMDD-HHMM.tar.gz     # 解出 data/ logs/
docker compose up -d
curl -s http://127.0.0.1:8765/health | python -c "import json,sys; d=json.load(sys.stdin); print(d['status'], d['stats']['count'], d['audit']['ok'])"
```

迁移到另一台机器：`tar` 包 + 同一个镜像（`docker save` / 私有 registry）即可；
用户、令牌、审计、设置全部跟着 `data/` 走，**不需要**重新初始化。

## 12. 常见问题（FAQ）

1. **`docker compose up` 报 `required variable TRACELENS_ADMIN_PASSWORD is missing a value`**
   没建 `.env` 或没填口令。`cp scripts/env.example .env` 并填一个 ≥10 位的口令；
   或临时 `TRACELENS_ADMIN_PASSWORD='...' docker compose up -d`。这是**故意的**：
   宁可起不来，也不要让管理员口令只出现在滚动日志里。

2. **容器 `running` 但 `docker compose ps` 显示 `(unhealthy)`**
   `docker inspect --format '{{json .State.Health.Log}}' tracelens | tail -c 600` 看最近一次检查输出。
   常见原因：进程没起来（`docker logs` 会有 Python 栈）、端口被别的进程占了（容器内 8765）、
   数据目录不可写（见第 3 问）。健康检查判的是 `/health` 200 + `status=ok`，不是端口通。

3. **入口包装报 `数据目录不可写：/app/var（uid=10001 gid=10001）` 并 exit 2**
   宿主 `./data` 属主不是 10001。修：`sudo chown -R 10001:10001 ./data ./logs`（Linux）；
   Windows Docker Desktop 的绑定挂载通常直接可写，实测没这个问题。

4. **忘了 admin 口令怎么办**
   两个办法：① 还有别的 admin → 让他登录后在"用户管理"里重置你的口令；
   ② 一个 admin 都没有 → 停容器、**备份后**删掉 `./data/auth/auth-state.json`，再 `up -d`：
   会按 `TRACELENS_ADMIN_PASSWORD` 重新 bootstrap 一个 `admin`。**实测**（本机）：删掉该文件后重启，
   控制台打印"首次启动：已创建管理员 admin，初始口令来自环境变量 TRACELENS_ADMIN_PASSWORD"，
   登录 200，且 `records.jsonl` 的 13 条记录与审计链都还在（只有账号/会话/令牌丢了）。

5. **登录后提示必须改密**
   设计如此：环境变量注入的只是**初始**口令（`must_change_password=true`），首登必须换成只有本人知道的口令。

6. **换宿主端口**
   `.env` 里 `TRACELENS_PORT=9000`（或 `TRACELENS_PORT=9000 docker compose up -d`），容器内始终 8765。

7. **日志在哪**
   `docker compose logs -f tracelens`（滚动日志，json-file 10m×3）+ `./logs/tracelens-YYYYMMDD.log`
   （入口包装用 tee 落的文件，含首启抬头）。注意日志里可能有一次性管理员口令。

8. **导入/webhook 报 500 `RECORD_STORE_WRITE_FAILED`**
   记录日志写不进去（卷只读/满/属主错）。查 `docker exec tracelens ls -ld /app/var` 与宿主 `./data` 属主；
   产品**宁可 500 也不假装"导入成功、重启就没了"**。

9. **`/health` 里 `audit.ok=false`，或 `/api/audit` 直接 500 `AUDIT_CHAIN_BROKEN`**
   `audit.jsonl` 被手工改过/截断过。审计是 append-only，不提供"修历史"；
   只能从备份恢复该文件，或接受"这段证据不可信"（断链时导出接口**拒绝出文件**，这是设计）。

10. **导出 PDF 结果下载到的是 HTML**
    镜像没装 reportlab（`TRACELENS_WITH_PDF=0` 构建的）。要么重建成默认（装 reportlab），
    要么接受 HTML（可打印，Ctrl+P 存 PDF）——响应头 `X-TraceLens-Export-Fallback` 会写明原因。

11. **离线机器怎么装**
    `docker load -i tracelens-0.4.5-image.tar`，然后 `docker run`/compose 起；镜像里没有需要联网的依赖，
    实测 `--network none` 也能跑。校验包完整性：`sha256sum -c SHA256SUMS.txt`。

12. **Apple Silicon / arm64 能用吗**
    **未实测**。镜像是 `linux/amd64`；在 M 系列上会走模拟（慢）或需要 `--platform linux/amd64` 构建。
    arm64 原生构建需要 reportlab 的 arm64 wheel，不确定时用 `TRACELENS_WITH_PDF=0`。

13. **重复 `docker compose up -d` 会不会把数据重置成演示 12 条**
    不会。只有 `records.jsonl` 不存在（真首启）时才写演示种子；已有数据一律沿用。

14. **怎么彻底重来**
    `docker compose down && rm -rf data logs && docker compose up -d`。**这会连审计一起删掉**，
    需要留证据的话先按 §7 备份。
