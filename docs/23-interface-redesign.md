# 23 · 功能中心视觉重做（档案 / 案卷方向）

> 方法论来源：`frontend-design` 技能（前端设计，v1.0.0）。该技能要求先定调、
> 再写令牌、最后逐条跑「反 AI 味」清单。本文是这次改版的交付说明。
>
> 适用范围：`agent_explainer/web/ext/workspaces.css` 全量重写 +
> `styles.css` 新增 16 个 `--ws-*` 令牌 + `workspaces.js` 增加一个有标页码。

## 1. 定调（写第一行 CSS 之前先定的四件事）

| 项 | 结论 |
| --- | --- |
| **目的** | 技术负责人逐个查看「Agent 做了什么、能不能回滚、证据在哪、对外怎么交代」，八件事各占一页 |
| **调性** | **档案 / 案卷（Editorial）** —— 一本装订好的卷宗，不是仪表盘 |
| **约束** | 离线桌面端（Electron 44 / Chromium 140）；中文为主；不得下载 webfont；单条动效 ≤200ms（`selfcheck` 第 1295 项硬门禁）；`workspaces.css` 必须纯 ASCII、只能引用 `styles.css` 已声明的令牌 |
| **记忆点** | **页边的朱砂印**：竖排索引编号 + 选中项的朱砂竖线 + 页头 `01 / 08` 页码，像在翻一份有编号的案卷 |

旧版为什么不算「有设计」：白底、12px 圆角卡片、统一阴影、居中图标、全部
`uppercase` 小灰标签 —— 正好命中技能第 4 条（一模一样的圆角卡片）和第 8 条
（纯色平背景、零氛围）。

## 2. 令牌（写在 `styles.css`，因为 `workspaces.css` 只允许引用）

| 令牌 | 亮色 | 含义 |
| --- | --- | --- |
| `--ws-paper` | `#f4f0e8` | 纸面（暖白，不是 `#fff`） |
| `--ws-paper-2` | `#fbf8f2` | 贴合上去的另一张纸（侧栏、面板） |
| `--ws-ink` | `#17140f` | 墨（暖近黑，不是 `#000`） |
| `--ws-ink-2` | `#4c453a` | 正文 |
| `--ws-ink-3` | `#6f6555` | 注记 / 标签（实测 5.04:1） |
| `--ws-rule` / `--ws-rule-2` | `#ded6c7` / `#c2b7a3` | 发丝线（普通 / 加重） |
| `--ws-accent` | `#a6381f` | **朱砂**，全页唯一强调色 |
| `--ws-accent-soft` | `#f4e5de` | 选中行底色 |
| `--ws-serif` / `--ws-sans` / `--ws-mono` | 见 §3 | 三档字体 |
| `--ws-dur` / `--ws-ease` | `320ms` / `cubic-bezier(.16,1,.3,1)` | 留给将来放宽上限时用；当前规则一律走 `--dur-*`（≤200ms） |

暗色不是另做一套，而是把纸墨互换（`prefers-color-scheme: dark`）：纸变 `#14120f`、
墨变 `#f2ebdf`、朱砂提亮到 `#e0663c`（实测 5.46:1）。组件规则一行未改。

## 3. 字体：三档，全部来自系统

技能禁止 Inter / Roboto / Arial / system-ui 当展示字。但这是一个**离线**桌面
产品，下载 webfont 会破坏「断网可用」，也会给热更包加几 MB。折中：

| 用途 | 字体栈 | 为什么 |
| --- | --- | --- |
| 展示（标题、索引数字、印章） | `Source Han Serif SC → Noto Serif SC → Songti SC → SimSun` | 宋体系是中文「档案」语感的来源；末位 `SimSun` 保证任何 Windows 都有衬线兜底 |
| 正文 | `DengXian → Noto Sans SC → Microsoft YaHei` | 等线比雅黑更几何、更少「系统默认」味 |
| 编号 / 哈希 / 小标签 | `Consolas → Cascadia Mono` | 等宽数字，`font-variant-numeric: tabular-nums` 让 01–08 对齐 |

**没有加载任何外部字体**：`workspaces.css` 里零 `@font-face`、零 URL。

## 4. 构成

- **侧栏是书脊**：244px，右侧一条发丝线；三组标题（记录与判定 / 协作与分析 /
  对外产出）用 `--ws-mono` 10px；每项是「编号 + 标题」的账目行，选中项靠**左侧
  2px 朱砂线 + 浅朱砂底**标记，不用胶囊、不用圆角。
- **页头是书眉**：宋体标题 `clamp(26px, 2.4vw, 34px)`、字距 −0.02em、行高 1.12；
  下面一条 1px 粗线 + 再下 4px 一条更淡的细线（印刷双线）；右上是页码 `01 / 08`。
- **总览是目录**：两栏、零圆角、零阴影，每项一条上边发丝线，编号 28px 宋体，
  标题 19px 宋体，描述 12.5px 正文，底部「打开 →」。八项按 01–08 排，读起来
  就是目录。
- **面板是一张纸**：`--ws-paper-2` 底 + 1px 边框 + 2px 圆角；标题前 12px 朱砂短线，
  与页头 eyebrow 同一个记号，让每个区块都像同一份文档里的一节。
- **计数器是表格**：四格之间只有竖发丝线，数字 30px 宋体等宽 —— 不用四个圆角小卡片。

## 5. 动效

| 项 | 规格 |
| --- | --- |
| 入场 | 浮层 200ms 淡入；八个条目 200ms 上浮（14px），**延迟 40/100/160/220/280/340/400/460ms** |
| 填充模式 | 条目用 `backwards`（延迟期间保持起始帧，动画没跑也不会消失） |
| 浮层 | **不用 `both`**：动画没触发时浮层就是可见的，不会被停在 opacity 0 |
| 微交互 | 150–200ms，只动 `color` / `border-color` / `gap` |
| 降级 | 全部包在 `@media (prefers-reduced-motion: no-preference)` 内 |
| 不做 | 卡片 hover 位移 —— 会把发丝线从邻行撕开，破坏整页赖以成立的账目线 |

> 技能给的场景过渡基准是 600–800ms，这里**主动不采用**：产品 `styles.css` 的
> 设计纪律写着「单条动效不超过 200ms」，`selfcheck` 第 1295 项会拦。错峰延迟承担了
> 「编排感」，单条时长仍然守规。

## 7. 可访问性（实测，不是目测）

| 组合 | 对比度 | 判定 |
| --- | --- | --- |
| `--ws-ink` on `--ws-paper` | 16.16:1 | ✅ |
| `--ws-ink-2` on `--ws-paper` | 8.32:1 | ✅ |
| `--ws-ink-3` on `--ws-paper` | 5.04:1 | ✅（小号标签达标） |
| `--ws-accent` on `--ws-paper` | 5.76:1 | ✅ |
| 暗色 `--ws-ink` on `--ws-paper` | 15.78:1 | ✅ |
| 暗色 `--ws-ink-3` on `--ws-paper-2` | 4.56:1 | ✅ |

- 焦点圈：统一 `2px solid var(--ws-accent)` + `2px` 偏移；表格式条目用 `-2px` 内偏移。
- 触控目标：窄屏导航项 `min-height: 44px`；桌面条目 38px（键盘可达，鼠标精度足够）。
- 语义：`section[role=dialog]` + `aria-modal` + `aria-labelledby`；页码 `aria-hidden`；
  导航项 `aria-current="page"`；总览卡片是真 `<button>`。

## 8. 三档宽度实测（1440 / 768 / 375）

用无头 Edge 截图实测，不是推断。**踩到的坑**：`--window-size=375,812` 在
headless 下被 Chromium 夹到 **492px**，截出来的 375 宽图其实是 492 布局的裁切，
于是「右侧被切」是假象。正确做法是把页面放进 **375×812 的 iframe** 再截，
布局视口才是真的 375。

| 宽度 | 结论 |
| --- | --- |
| 1440 | 两栏目录、账目线逐行对齐、`打开` 落在同一基线 |
| 768 | 单栏，条目高度改为 `min-height: 0`（否则桌面行高在单栏里只是空白） |
| 375 | 书脊变横向索引条（仍是有编号的横条，不是胶囊）；页头标题占整行、页码隐藏、关闭按钮移到右上角 |

窄屏还修了一处：标题 `max-width: 18ch` 让断行落在逗号后。原先用
`text-wrap: balance` 会把「页面」从中间劈开 —— CJK 没有空格，平衡算法无从遵循。

## 8bis. 节奏压缩（一屏目录）

1440×980 视口（Chromium 实际可视区约 1414×887）下，八条 + 简介行原溢出 107px。
压缩后（`--dump-dom` 实测，非目测）：

| 指标 | 压缩前 | 压缩后 |
| --- | --- | --- |
| 条目高 | 177px | 154px（内距 10/12、内隙 6、描述行高 1.6） |
| 简介区 | 162px（纵排三段） | kicker 一行 + deck line（标题左、尾注右） |
| 最后一条 bottom | 994 | **859 < 887 ✓** |

492px 视口复测：`docSW = vw`（零横向溢出）；lead 起于行首（left=16），
note 换行后 `margin-left:auto` 右对齐；顶部导航条 `overflow-x: auto` 可滚动。

## 10. 如实申报

1. **没有在真实 Electron 窗口里目视确认**：沙箱不允许启动 GUI 进程。上面的截图
   是同一份 `styles.css` + `workspaces.css` 在 Chromium 140 里的真实渲染，但
   字体回退顺序、系统缩放（125%/150%）下的表现仍需你亲眼过一遍。
2. **宋体在部分机器上会退回宋体（SimSun）**：视觉从「思源宋」变成「中易宋」，
   字重更硬、更接近印刷品 —— 仍在方向内，但不是同一个字形。
3. **纸纹是 3.5% 的 SVG 噪点**：极低对比，某些显示器上可能完全看不出。这是刻意的。
