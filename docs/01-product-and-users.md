## 0. 给不懂技术的读者：30 秒看懂这份文档

这份文档回答四个问题：

1. **这个产品是什么**：一个装在自己电脑上的程序。它读 AI 助手干活时留下的流水记录，然后翻译成一张"人话行动清单"。
2. **给谁用**：用 AI 助手干活、但看不懂技术日志的人，以及需要事后拿出证据的团队。
3. **做什么、不做什么**：第 4 节只列了 6 件"非做不可"的事，其余全部排到后面或明确不做。
4. **怎么算做好了**：第 7 节给了可以用数字验证的标准，不靠感觉。

文中所有技术词都在第 2 节有"一句话解释"，正文遇到时会顺手解释一次。

**最重要的一个前提（请务必先知道）**：目前我们**没有任何真实的 AI 运行记录样本**。项目里所有演示数据都是团队自己按公开规范**手工编造的假数据**。这意味着"翻译得好不好"只能靠人工判断，不能靠真实数据回归。详见第 8 节假设 A1。

## 1. 产品定义

### 1.1 一句话定位

> **TraceLens（行动透镜）是一台"翻译机"：它把 AI 助手干活时留下的记录（trace）实时翻译成一张普通人能扫读的行动清单——它做了什么、为什么、现在要不要你拍板、你该点哪个按钮——装在自己电脑上就能用，团队也能部署到服务器上一起看。**

三个刻意的性格（与"日志查看器"区分开）：

| 性格 | 含义 | 反面（我们不做成什么样） |
|---|---|---|
| **结果导向** | 每条记录必须回答"所以呢"，而不只是"发生了什么" | 不做"把日志排个版好看一点" |
| **可干预** | 清单不是只读的：卡点可以当场同意、改参数、拒绝 | 不做"只能看不能动"的报表 |
| **可证明** | 事后能按时间回放、能一键导出不可篡改的记录 | 不做"解释被润色后无法核对"的黑箱 |

### 1.2 目标用户

**核心用户（买单/使用的人）**：正在用 AI Agent（智能助手）处理日常工作，但**不读技术日志**的人。分成三类，后文称 **A 小白 / B 普通 / C 谨慎**：

- **A 小白**：完全不懂技术，只希望"它帮我把事做完，别让我猜"。
- **B 普通**：用过 ChatGPT 这类产品，知道 AI 会"调用工具"，但不看细节，希望"不用一直盯着"。
- **C 谨慎**：技术或半技术岗位（运维、财务、法务、数据治理、IT 管理员），需要"每一样被改动的东西我都能证明"。

**次级用户（团队模式）**：需要共用同一套数据的团队里的**管理员**（管账号）、**编辑者**（能干预）、**查看者**（只能看和导出）。

**不是我们的用户**：要自己搭可观测平台、要看 span 级火焰图调优的性能工程师（他们该用 Langfuse）；要训练模型的算法工程师；要在手机上聊天的普通消费者。

### 1.3 解决什么问题：四个断层

AI 助手"想什么、做了什么、卡在哪"对人是不透明的。这个不透明裂成四个断层，每个断层都能被用户原话说出来：

| 断层 | 用户原话 | 现状为什么难受 | TraceLens 的补法 |
|---|---|---|---|
| **D1 看不见** | "它到底在跑还是死了？" | 进度不可见 → 反复刷新、焦虑、以为卡死 | 实时进度 + 三区分层视图（已完成 / 进行中 / 需要我） |
| **D2 看不懂** | "这堆 trace、span、tool call 是什么？" | 术语墙 → 直接放弃打开 | 翻译层：每条一句话人话，术语默认不出现 |
| **D3 插不上手** | "它问我要不要继续，我哪知道在问什么？" | 确认弹窗不含后果 → 闭眼点"是"，或干脆不敢点 | 干预闭环：为什么需要你 + 三个选项 + 每个选项的后果 |
| **D4 说不清** | "谁能证明我没乱批？" | 无留痕 → 出事后无法自证、无法交付复盘 | 不可篡改审计日志 + 一键 CSV/PDF 导出 |

**产品假设（核心）**：只要把这四个断层补上，普通人就能把 AI 助手当"同事"而不是当"抽奖机"使用——**敢用、能拦、可交代**。

### 1.4 与 Langfuse 等 trace 工具的关系

一句话：**我们是它们的"下游翻译层"，不是它们的替代品，也绝不做它们的采集端。**

| 关系维度 | TraceLens 的做法 | 明确不做 |
|---|---|---|
| **数据方向** | **只读接入**：从 Langfuse / OpenTelemetry / MCP 事件流 / 本地 JSON 文件**读取**已存在的记录 | 不自建采集 SDK 去抢 Langfuse 的活；不修改、不回填、不删除原始 trace |
| **数据所有权** | 原始记录留在用户自己的平台；TraceLens 只存自己需要的标准化副本（本机 SQLite / 自建服务器卷） | 不把数据上传到我们的云端（我们没有云端） |
| **价值层** | 翻译层 + 决策层：把人话清单、干预按钮、审计证据放在 Langfuse 之**上** | 不做图表大盘、不做性能火焰图、不做告警规则引擎 |
| **用户分工** | 工程师继续用 Langfuse 排查；非技术用户用 TraceLens 决策。两者互不干扰 | 不要求用户"迁移"，不要求"先装 Langfuse 才能用我们" |
| **无 trace 时** | 降级可用：**演示数据**、**粘贴 JSON**、**上传文件**、**webhook/SDK 实时上报** 四种入口都不依赖 Langfuse | 不承诺"接入任意私有格式零配置" |

**类比**：Langfuse 是飞机的**黑匣子和仪表盘**（给工程师看）；TraceLens 是**副驾驶的语音播报**（给乘客和机长听），外加一个"要不要现在改航向"的确认按钮。仪表盘不会被语音播报取代，语音播报也不需要拆掉仪表盘。

**商业含义**：客户已有 Langfuse/OTel 时，我们的部署成本是"加一个只读接入 + 一个前端"，**零迁移**，这是 Must 功能 M3/M4 只读设计的直接理由。

### 1.5 三种交付形态（每种都必须真的能交付）

| 编号 | 形态 | 给谁 | 用户视角的承诺 | 技术一句话 |
|---|---|---|---|---|
| **D-1 桌面安装包** | Windows x64 安装程序（NSIS），自签名 | A 小白、B 普通、C 谨慎的个人桌面 | 双击安装 → 开始菜单打开 → 直接看到演示清单，全程不用装 Python | Electron 外壳 + 内置 Python 本地服务（sidecar）+ Web UI |
| **D-2 便携版** | 免安装 zip 解压即用 | 公司电脑装不了软件的人、要拷给同事演示的人 | 解压 → 双击 exe → 浏览器自动打开 | 同一套程序，数据落在解压目录，不写注册表 |
| **D-3 Docker 镜像** | 官方镜像 + `docker-compose.yml` | C 谨慎、团队管理员 | 一条命令起团队服务器，同事用浏览器访问 | `python:3.12-slim` 多阶段构建、非 root、数据挂卷持久化 |

**为什么三种都是 Must**：只给安装包 → 团队没法共享数据；只给 Docker → 非技术用户根本跑不起来；只给源码 → 小白零机会。三者缺一，产品就不是"独立产品"，只是一个 demo。

**已知诚实限制（必须在文档与界面里说清）**：代码签名是**自签名**（自己给自己发的证书），Windows 的 SmartScreen 仍会弹"未知发布者"警告。我们提供 SHA256SUMS 校验文件和 `.cer` 证书用于**完整性核对**，但**不能保证** SmartScreen 不报警。任何"签名后即可无缝安装"的表述都是虚假承诺（详见 t12/t16）。

### 1.6 双模式：个人模式（local）与团队模式（team）

| 维度 | 个人模式 local（默认） | 团队模式 team |
|---|---|---|
| 启动方式 | 桌面 exe / 便携版直接打开，**免登录** | Docker 或服务器部署，`--mode team`，**必须登录** |
| 账号 | 自动使用本机默认用户 | admin / editor / viewer 三种角色，多账号 |
| 数据 | 只在本机 | 存服务器卷，成员共享同一份数据 |
| 干预权限 | 全部可用 | editor + admin 可干预；viewer 只读 |
| 模型配置 | 本机设置页可改，key 用系统加密（DPAPI） | **仅 admin** 可改，key 用环境变量注入，禁止明文入库入日志 |
| 典型人 | 一个人用 AI 干活的员工 | 5–30 人小团队，一台自建服务器 |

**产品护栏（不可违反）**：超时**绝不**自动同意，只能挂起并提醒。人永远有最终按钮。

## 2. 术语卡（每条一句话，全文统一口径）

| 术语 | 一句话解释（面向非技术读者） |
|---|---|
| trace（运行记录） | AI 助手干一件事留下的完整流水账，像行车记录仪。 |
| span / observation | 流水账里的一条"某步骤花了多久、输入输出是什么"，是 trace 的组成单元。 |
| Langfuse | 一个流行、开源的运行记录存放与查看平台，我们只读它的数据。 |
| OpenTelemetry / OTLP | 业界通用的记录格式标准，很多系统在往它写数据，我们也能读它。 |
| MCP 事件流 | 工具调用类程序产生的一串事件消息，也是一种可接入的数据源。 |
| webhook | 别人的程序主动把新记录"推"给我们的接口，我们不用一直去问。 |
| SDK | 给开发者用的现成小工具包，加两行代码就能把记录发给我们。 |
| SSE | 服务器往浏览器"持续推送新消息"的技术，用于实时刷新清单。 |
| Electron | 把网页打包成 Windows 桌面程序的常见外壳，我们用它做桌面端。 |
| sidecar（边车进程） | 桌面程序启动时顺带在后台拉起的服务进程，只在本机监听。 |
| 便携版 | 免安装、解压即用、不写注册表的绿色版本。 |
| Docker 镜像 / 容器 | 把程序和它需要的一切打包成"即插即用盒子"；盒子跑起来就是容器。 |
| docker-compose | 用一个文本文件一键启动容器并配好端口、存储、密码的编排工具。 |
| SQLite | 单文件本地数据库，不用装数据库服务器，适合单机/小规模团队。 |
| JSON | 机器用的结构化文本格式，是用户能粘贴/上传给我们的数据形态。 |
| JSONL | 一行一条 JSON 的追加式文本文件，我们的审计日志用它。 |
| 哈希链 | 每条记录都含上一条的"指纹"，改任何一条都会校验失败，用来防篡改。 |
| 审计日志 | 谁在什么时间批准/修改/拒绝了什么的不可删除记录。 |
| LLM（大模型） | 会写文字的 AI，可用来把清单句子写得更自然，**默认关闭**。 |
| token | 模型计费用的文字单位，也是"这次花了多少钱"的估算依据。 |
| i18n | 界面文案支持多语言（本项目中文/英文）的工程做法。 |
| 干预 | 用户在卡点做出的决定：同意 / 修改参数 / 拒绝。 |
| 角色 admin/editor/viewer | 管理员管账号和配置；编辑者能干预；查看者只能看和导出。 |
| DPAPI | Windows 自带的本机加密能力，用来保护模型 API key。 |
| SmartScreen | Windows 对"不认识的发布者"弹的安全警告窗，自签名无法完全避开。 |
| SHA256SUMS | 一组文件指纹，用来核对下载包是否被改动过。 |
| MoSCoW | 优先级分法：Must 必须、Should 应该、Could 可以、Won't 不做。 |
| SUS | 2 分钟可做完的 10 题"好用程度"打分表，68 分以上算及格。 |
| 演示数据 | 团队**手工编造的假记录**，用来让产品第一次打开就有东西看。 |

**解释粒度三档（全文统一，任何地方出现 L1/L2/L3 都是这个意思）**：

- **L1 结果级**：一句话结论 + 现在状态 + 需要你做什么（不超过 2 行）。
- **L2 步骤级**：3–7 条关键步骤，每步一句"为什么" + 影响范围（文件/金额/系统）。
- **L3 参数级**：工具名、入参出参、耗时、成本、依据、可回溯的证据链。

长度硬约束：L1 ≤ 40 字；L2 每步 ≤ 30 字；L3 单条 ≤ 120 字（供 t4 翻译引擎与 t6/t7 界面共用）。

### 3.1 用户画像主表（任务要求的五列，逐列齐全）

| **C 谨慎**<br>（运维/财务/法务/数据治理/管理员） | ① 生产环境配置变更（AI 改配置文件、改权限）；② 付款与报销审批；③ 客户数据批量导出（含个人信息）；④ 合同条款修订后归档 | P5 无法证明"它做了 A 没做 B"；P11 多人共用时说不清谁批的；P13 怕 trace 里的客户数据外泄；P14 需要在服务器上给全组看、要权限分级 | **L3**（默认全展开）+ 必须可导出为 CSV/PDF | 干预前必须看到**影响面预览**（哪些文件/表/金额/外部接口）；修改参数需**逐字段核对**；每次干预**写入不可篡改审计**；拒绝必须填原因；**绝不允许自动同意**；viewer 角色只读 |

| 维度 | A 小白 | B 普通 | C 谨慎 |

| **T5 被要求拍板**（首次干预） | 蓝色卡片弹出："要删除 12 个临时文件，需要您确认" | 卡片写清**为什么需要你 + 影响面（哪些文件）+ 三个选项（同意 / 修改参数 / 拒绝）+ 每个选项的后果**；提交后条目状态即时变化，审计写入 | **焦虑峰值**（A 最怕这里） → **安全感**（知道点了会怎样） | 蓝色高亮卡 + 影响面清单 + 三按钮带后果文案 | 超时只挂起提醒，**绝不自动同意**；修改参数逐字段可核；拒绝必填原因 | M6 S4 |
| **T6 出岔子** | 某步变红，AI 卡住 | 红卡显示"哪一步失败 + 人话原因（术语已翻译）+ 建议动作 + 重试入口" | 惊慌 / 自责 → **有路可走** | 失败卡三要素 + 一键重试 + 展开看原始记录 | 不许只显示错误码；重试不得清空已成功的步骤 | S1 M4 |
| **T7 事后交代** | 被上级/审计问"它到底改了什么？谁批的？" | 拖时间轴逐步回看；点导出，30 秒内拿到 CSV / 可打印清单，含每次干预的人与时间 | 被追问的压力（C 最怕这里） → **有据可查的底气** | 时间轴 + 筛选 + 导出（含审计哈希链校验说明） | 审计不可删改；导出不得含 API key；日志需脱敏 | M6 S3 S5 |

**情绪曲线（关键判断）**：A 类的情绪低谷在 **T5**（被要求做决定），C 类的低谷在 **T7**（被追问举证）。产品必须在这两点各设一个"安全感锚点"：

- **T5 锚点**：不是一个是/否按钮，而是"为什么需要你 + 你有三个选择 + 各自的后果"。
- **T7 锚点**：一键导出防篡改证据，30 秒内完成。

第二个低谷是 **T1**（装不上）——这是 A 与 C 共同的流失点，因此便携版与 Docker 是"装不上"的两条逃生通道，属 Must。

## 6. MVP 范围

### 6.1 MVP 里有什么

**MVP = 6 项 Must（M1–M6） + 2 项 Should（S1 失败解释、S3 时间轴与侧边栏）**。

选 S1/S3 进 MVP 的理由：没有失败解释，第一天的实测一定会在异常处卡死；没有时间轴，C 类用户无法完成"事后查哪一步动了文件"的核心任务。其余 Should（S2 LLM 润色、S4 影响面预览、S5 PDF、S6 用户管理页、S7 对比）排在 MVP 之后、v1.x 之内，**不阻塞验收**。

MVP 完成的定义（可执行判据）：

1. 干净 Win10/11 x64 上安装并启动桌面端，**5 分钟内**看到演示行动清单；
2. 便携版解压即用，数据落在自身目录；
3. `docker compose up` 起团队模式，能登录、能按角色看到不同权限；
4. 粘贴 / 上传 / 实时三种入口至少各跑通一次（自造样本）；
5. 能同意、能改参数放行、能拒绝，并 30 秒内导出审计 CSV；
6. 中英切换无残留；无 API key 时产品功能完整。

### 6.2 MVP 之后（v1.x）

S2 LLM 润色默认关闭策略下的正式化、S4 影响面预览、S5 PDF 导出、S6 用户管理页、S7 对比模式，以及 C1–C6。

### 6.3 明确不做（Out of scope，汇总口径）

W-01 自建采集 SDK / 替换 Langfuse；W-02 自动执行高危、超时自动同意；W-03 自动回滚；W-04 图表大盘与火焰图与告警；W-05 AI 定责仲裁；W-06 IM/工单集成；W-07 本地离线小模型；W-08 移动原生 App 与云同步；W-09 我们托管数据的 SaaS 多租户；W-10 任意私有格式零配置适配。

**新增越界请求处理规则**：任何人提出上述十项之一，默认答复"进 Won't，需产品与发起人共同决策才能移出"，不在子任务里顺手实现。

| `user_intervention`（决策 + 修改前后参数 + 原因 + 时间 + 人） | M6、K-07/K-08 | 干预闭环与审计对齐 |

| `error.code` / `error.human_reason` / `suggested_next` | S1 | 失败卡三要素 |
| `raw_ref`（未知字段收纳） | M3、W-10 | 未知数据不丢，但不参与翻译 |
| 审计事件（`ts/actor_id/decision/original_params/modified_params/reason/client_info` + `prev_hash`/`hash`） | M6、K-09 | append-only 哈希链，禁止 UPDATE/DELETE |

**三条架构约束建议**（t2 若不接受，需在队长处显式变更）：
1. `human_readable` 不得是唯一事实来源，必须能由结构化字段重新生成（否则护栏 P3 与 K-05 无法验证）。
2. 审计日志与业务表分离，append-only，运行账号无 UPDATE/DELETE 权限。
3. 指标埋点（7.3）与审计分离存储，两者都不得记录 API key 与 trace 原文。

### 9.2 给后端（t3/t4/t5/t8/t9/t13/t14/t15/t17）

- **演示数据（t3）必须满足**：`samples/action_records.json` 原生格式 ≥ 12 条，覆盖 ≥ 10 类 `action_type`；其中 ≥ 3 条 `requires_action=true` 且带 `intervention_options`（含后果文案）、≥ 1 条失败（含 `error.human_reason` + `suggested_next`）、≥ 1 条高危写操作（含 `impact_scope`）、≥ 1 条含敏感路径（演示脱敏导出）。三种外部格式夹具各 6–10 条，文件头与 `samples/README.md` 注明"合成示例，非真实采集"及依据的规范版本。
- **翻译引擎（t4）**：四要素齐全、zh/en 各自原生模板（不是占位翻译）、缺失字段有降级文案、单条长度遵守 A9。
- **LLM 增强（t5）**：默认 `template`，无 key 不崩溃；提示词包含用户偏好/任务名/历史摘要/输出语言。
- **干预（t8）**：非法参数返回可读错误；界面在 API 不可用时降级本地模拟并提示。
- **审计（t9）**：篡改必须校验失败；导出 ≤ 30 秒（K-09）。
- **实时（t14）**：webhook 幂等 + 鉴权；SSE 断线重连 + 降级轮询；SDK 示例一键可跑。
- **设置（t15）**：key 仅回显掩码、桌面 DPAPI、团队环境变量、`test-llm` 错误可读。
- **Docker（t17）**：`GET /health` 200 且 `status:"ok"`（现状无 `/api/health` 路径）、卷持久化、首次 admin 密码可见性说明（现状环境变量 `TRACELENS_ADMIN_PASSWORD`，一次性密码只出现一次）。

### 9.3 给前端（t6/t7）

- 颜色编码统一：绿=完成、黄=进行中、红=出错、蓝=待确认；颜色不得作为唯一信息载体（无障碍）。
- 三区结构：`已完成 / 进行中 / 需要我`，"需要我"永远置顶高亮；**同一时刻最多展示 1 个待确认**（队列串行）。
- 默认 L1，永不默认 L3；展开逐层进行。
- 移动端 ≤ 480px：悬浮球（任务名 + 进度环）→ 底部面板三区；桌面 ≥ 1024px：侧边栏 + 时间轴 + 对比模式。
- 全部文案走 i18n 字典（zh/en），顶部语言切换并持久化；演示数据横幅/徽标常驻，文案："合成演示数据 · 非真实采集"。
- 演示数据需内嵌 ≥ 12 条记录，静态打开即可演示（不依赖后端）。

### 9.4 给测试（t10/t11）

- 11 个测试任务应与 M1–M6 + S1/S3 一一对应（桌面安装启动、演示导入、粘贴 JSON、上传 trace、webhook 实时接入、中英切换、干预三操作、审计导出、团队登录与角色、模型配置、Docker compose 部署）。

- 第 3.5 节 H-A ~ H-E 是**画像假设的验证清单**，t11 报告须逐条给出成立/不成立与证据。
