## 0. 30 秒看懂

这份文件回答五个问题：

1. **测什么**：5 个典型场景、10 个测试任务，覆盖桌面安装、演示导入、粘贴 JSON、上传 trace、webhook 实时接入、中英切换、干预三操作、审计导出、团队登录与角色、模型配置、Docker compose 部署。
2. **谁来测**：招募 **5 名非技术用户**（小白 2 名 / 普通 2 名 / 谨慎 1 名），每人 **45 分钟**；Docker 部署是独立的运维任务，不占用户 45 分钟。
3. **怎么测**：主持人按逐字脚本执行，用户边做边讲；每个任务都有观察点与成功判定，不靠“感觉还行”。
4. **怎么记**：计时、截图、原话、错误、提示次数；问卷见 [05-questionnaire.md](./05-questionnaire.md)。
5. **哪些现在不能测**：桌面安装包/便携版（t12 未交付）、Docker（t17 未交付）——**这两类一律记 BLOCKED，不许记通过**。粘贴/上传 UI、审计导出 UI 已交付，按 T02/T03/T07 走界面；真实用户自己跑的一版见 [05-real-user-kit.md](./05-real-user-kit.md)。

**三条贯穿全文的护栏**（来自 PRD 与架构纪律）：

| 护栏 | 测试里怎么体现 |
|---|---|
| 只读接入、不索要真实 trace | 全部用 `samples/` 的**合成演示数据**与团队自造夹具；用户若粘贴真实客户数据，立即停止并删除 |
| 决定 ≠ 生效 | 干预后只允许出现“决定已记录；是否生效取决于执行端是否接入”；出现“已强制停止 / 已生效”即记缺陷 |
| 诚实交付 | 没交付的形态记 BLOCKED；构建、安装、`docker build` 必须真实执行，禁止用静态检查冒充 |

### 1.3 明确不做（本任务范围外）

- 不做功能回归测试套件（那是 `tests/` 的职责）；不重复 `python -m unittest` 的断言。
- 不做性能压测、安全渗透、移动原生 App 测试；性能只按 PRD K-04 做首屏计时观察。
- 不要求用户提供真实 trace，不连接真实 Langfuse 服务器（假设 A1/A4）。
- 不验证 HTTPS 反向代理（由用户自建反代承担，A8）；T10 只验证容器内 HTTP 与健康检查。
- 不把 5 人样本写成统计结论；H-A~H-E 只给“成立/不成立/证据不足”。

### 2.2 三条“不得冒充”的规则

1. **未交付 ≠ 通过**。安装包、便携版、Docker 没产物时，结果只能写 `BLOCKED-T12` / `BLOCKED-T17`，并附“缺什么、谁来补”；源码跑通只证明逻辑，不证明打包。
2. **有入口 ≠ 端到端通过**。T02/T03 的导入面板已交付；必须同时验证“有效导入 → 刷新/重启仍在”和“非法输入可读”；只测空校验不算通过。审计导出也要验证“下载文件行数 = 链计数”。
3. **“决定已记录”不是“已生效”**。审计里只出现 `decision`，执行回执仍是 `unreported` 或演示值；任何“已停止/已执行”的界面文案都记缺陷；语言切换/外部决定后必须核对 `/api/records` 与页面一致（t11 B-01/H-03）。

### 2.3 统一测试目录与命名（避免污染仓库、避免路径歧义）

> 下文用 `agent-explainer\` 表示**仓库根目录**（含 `agent_explainer\` 的那一层）。路径含空格或中文时，PowerShell 里要加引号。示例假设仓库在 `C:\TraceLens\agent-explainer`；实际位置不同就替换，不要照抄盘符。

```powershell
$env:QA = "$env:TEMP\TraceLensQA"
New-Item -ItemType Directory -Force $env:QA | Out-Null
```

| 团队服务端口 | `8767`（避开本地端口，便于同一台机器同时开两个） |

### 3.5 45 分钟场次与轮换模块

**5 名参与者、5 场、每场 45 分钟**。每场都走同一段“核心闭环”，再按分配做一个“轮换模块”；这样既能横向比较，又能覆盖全部 10 个任务。

### T10 Docker compose 部署（独立运维任务）

| 项 | 内容 |
|---|---|
| 覆盖 | 真实 `docker build`、`docker compose up`、`GET /health`、团队登录、卷持久化、非 root |
| 执行者 | 运维/后端 + 测试官（可加 P5 旁观） |
| 预算 | 45 分钟（不含镜像构建等待；构建耗时可另计） |
| 现状 | **未交付**：仓库没有 `docker/`，t17 未完成；本轮记 `BLOCKED-T17` |
| 证据 | `docker info` 原始输出、镜像 ID、health JSON、登录截图、重启前后计数、`id` 输出 |

**前置条件**

1. 发起人已安装 **Docker Desktop**（Windows + WSL2 后端），`docker` CLI 在 PATH；本机可运行 `docker info`。
2. 交付包里有 `docker/Dockerfile`、`docker/docker-compose.yml`、`docker/entrypoint.sh`、健康检查脚本（t17 产物）。
3. 端口 8000 空闲；卷目录可写；`.env` 里只放测试口令，不提交、不截图明文。
4. **第一步必须真实执行 `docker info`**；不通过就停止并报告，禁止用 YAML 校验/静态检查代替。

**步骤**（以下 compose 命令统一加 `-f docker\docker-compose.yml`；若 t17 用 `compose.yaml`，换成实际文件名）

1. **预检（硬闸门）**：依次执行并记录完整输出/退出码：
   ```powershell
   docker version
   docker info
   docker compose version
   ```
   任一失败 → 记录 `BLOCKED-DOCKER-PREFLIGHT`，停止；向发起人请求安装/启动 Docker Desktop。
2. **构建（真实）**：
   ```powershell
   cd "C:\TraceLens\agent-explainer"
   docker compose -f docker\docker-compose.yml build
   ```
   文件名以 t17 交付为准（`docker-compose.yml` 或 `compose.yaml`），不要自己造。记录镜像 ID、构建耗时、退出码；构建失败立即停止，抄最后 30 行。
3. **启动**：在 `docker/.env` 设置 `TRACELENS_ADMIN_PASSWORD=<测试口令>`；`docker compose up -d`；`docker compose ps` 确认容器 `healthy`（或等 healthcheck 通过）。
4. **健康检查**：
   ```powershell
   Invoke-RestMethod "http://127.0.0.1:8000/health" | ConvertTo-Json -Depth 4
   ```
   预期 HTTP 200、`status="ok"`、`mode="team"`、`audit.durable=true`、`ingest.enabled=true`、`auth.bootstrap_needed=false`；**没有** `/api/health`、没有 `ready` 字段（不要按旧文档找）。
5. **登录与角色**：浏览器打开 `http://127.0.0.1:8000/`；用 admin + 环境变量口令登录；确认清单可见；至少验证 viewer 无干预入口（可现场建号或用现成账号）。
6. **持久化**：记录当前审计 count、用户数、设置 revision；`docker compose restart`；重新检查：
   - 审计 count 保留、用户可登录、设置保留（卷持久化）；
   - **演示记录 count 回到 12**（当前没有持久记录存储）——这是与 M2“重启数据不丢”的**已知差异**；若 t17 未补，必须记 `FAIL-M2-RECORDS`，不能记通过。
7. **非 root**：`docker compose exec <service> id`；预期 uid ≠ 0；`docker compose exec <service> ls -ld /data` 可写；记录输出。
8. **离线包（可选）**：`docker save` 生成 tar，算 SHA256；确认可在无网机器 `docker load`（若时间允许）。
9. **清理**：`docker compose down`（保留卷）；删除 `.env` 中的测试口令；保留镜像供复测。

**观察点**

- 构建/启动/健康检查全部是真实命令，有退出码与原始输出；没有“看着像起来了”。
- `/health` 的 `audit/ingest/settings` 块与实际启动参数一致；断链时 `audit.ok=false` 且 `status=degraded`（可另做篡改实验）。
- 卷里能看到 `audit.jsonl`、`auth/`、`settings.json`、`ingest/tokens.json`；记录数据不在卷里（当前内存）。
- 容器非 root；端口只暴露必要的一个；日志无密钥/口令。

**成功判定（M2 口径）**

- [ ] `docker info` 真实通过（记录原始输出）。
- [ ] `docker build` 真实成功（镜像 ID + 耗时）。
- [ ] `compose up` 后 10 分钟内 `GET /health` 200 且 `status="ok"`（K-01 的 Docker 口径）。
- [ ] admin 可登录；viewer 不能干预。
- [ ] 重启后审计/用户/设置保留。
- [ ] 非 root 运行。
- [ ] **记录持久化**：当前预期失败（记录回 12 条）→ 记 `FAIL-M2-RECORDS`，M2 **不通过**，由 t17 补持久化或队长显式降级。
- [ ] 未交付时：全部记 `BLOCKED-T17`，M2 不通过。

**失败 / 停止规则**

- `docker info` 失败：立即停止，按第 17 节前置条件上报；**禁止**改用静态校验或改本机 Docker 配置。
- 构建失败：停止，保留完整错误；不要修改 Dockerfile 让它“看起来能过”。
- 健康检查失败：保留容器日志（`docker compose logs`）与 `/health` 原文，停止。
- 发现记录持久化缺失：如实记失败并上报队长；**不得**把“审计还在”写成“数据不丢”。

## 9. 缺陷分级、停止规则与伦理

### 9.1 严重度

| 级别 | 定义 | 例子 | 处置 |
|---|---|---|---|
| **阻断（blocker）** | 核心任务无法完成，或数据/隐私受损 | 干预 500 且记录丢失；审计可被改而不报错；viewer 能批准；安装后打不开 | 停止该场，立即上报队长；修复后回归 |
| **高（high）** | 任务能完成但结果错误/严重误导 | 状态与审计不一致；修改参数越界仍写入；en 界面大量中文；模板模式必须 key | 本场记录，t11 前修 |
| **中（medium）** | 明显摩擦，有替代路径 | 找不到设置入口；错误消息太技术；刷新后语言丢 | 排期修，不阻断 |
| **低（low）** | 文案/对齐/轻微不一致 | 标点、间距、英文大小写 | 批量修 |

### 9.2 立即停止规则

1. 参与者要求退出或表现出明显不适。
2. 出现真实客户数据/真实密钥（用户粘贴、截图、日志）→ 停止、删除、记录事件。
3. 发现数据外发、密钥明文、审计可篡改而不报错。
4. 安装/运行导致系统异常（蓝屏、杀软隔离、无法卸载）。
5. Docker 前置不满足（`docker info` 失败）→ 停止 T10，改约。
6. 测试环境被污染（端口占用、数据错乱）→ 复位后重测；不要“带着脏数据继续”。

### 9.3 隐私与数据保留

- 只用合成演示数据与自造夹具；**禁止**真实 trace、真实客户名、真实金额、真实路径。
- 录屏/录音只存本机；30 天内删除；报告中用 P1–P5 代替姓名。
- 截图中若含密钥/口令/邮箱，先打码再入报告；无法打码就删图重截。
- 测试结束后删除 `$env:QA` 下的审计/设置/导出副本；产品 `var/` 若被使用，按交付说明清理。
- 审计的 `reason` 是自由文本，服务端不会对自由文本里的邮箱/电话打码；**测试理由里不要填真实个人信息**（已知边界，建议后续补自由文本脱敏）。

### 9.4 伦理

- 不欺骗：开始就说“这是测试产品，不是测试你”。
- 不引导：不替用户点、不暗示“正确答案”；提示按 H1–H3 记录。
- 不胁迫：报酬与结果无关；可以随时退出。
- 可访问性：当前不支持读屏；如参与者需要，改约或记录为“未覆盖”。
- 不公开用户原话到产品外；引用时用编号。
