# 24. 主动作页：账目式重排（ACTION-LEDGER-1）

> 需求：老板给出桌面端截图，要求「重做这一页的 UI 设计，风格要和功能中心类似，
> 行动清单也要重新排版，现在的行动清单排版空间利用率很差，提高空间利用率和优化
> UI 设计，让界面看起来更连贯」。
>
> 版本号**未提升**，仍是 `0.5.0`。只改界面层：新增 `ext/ledger.css`（覆盖层）、
> `index.html` 加载一行、`tests/test_ledger_face.py` 12 项守卫。后端、路由、字典
> 一字未动（契约 61 条、i18n 1565 键不变）。

## 1. 诊断（改前截图）

真实页面用无头 Edge 渲染 `index.html?frame=1440x900`，与老板截图是同一套布局：

| 区域 | 改前 | 问题 |
| --- | --- | --- |
| 左栏 | 白色圆角卡片 + 彩色状态胶囊 | 与主体割裂，胶囊三色各说各话 |
| 书眉 | 白底圆角条 + 一排彩色 chip | 占约 147px（768 高视口的 19%） |
| 演示声明 | 黄色大卡，标题 + 说明 + 三个 chip | 约 90px |
| 中间时间轴 | 白色圆角卡 + 滑块 + 「当前这一步」卡 | 约 220px |
| 行动清单 | 三张彩色软底圆角卡（auto-fit ≥280px 时纵向堆叠），卡内再套白色圆角卡 | **双层卡片**，一条记录占 4~6 行高度 |
| 右栏 | 白色圆角卡 + 圆点刻度 + 导入面板 | 与中间重复一份导入面板 |

三段头部（书眉 + 声明 + 时间轴）合计吃掉 768px 视口的 **44%**，行动清单被推到
屏幕下半部，513 条已完成记录还会把另外两区一起顶出视口。

## 2. 定调：与功能中心同一套语言

复用 `styles.css` 里已声明的 16 个 `--ws-*` 令牌，不新建调色板：

- 暖纸 `#f4f0e8` / 暖墨 `#17140f` / 单一朱砂 `#a6381f`
- 展示用宋体栈，正文 DengXian/Noto Sans SC，编号与时间用 Consolas 等宽数字
- **零圆角、零阴影、零彩色软底**，全部分隔用 1px 发丝线
- 暗色只靠 `prefers-color-scheme: dark` 下令牌互换，组件规则一行不改
- 字体全部取自系统，零 `@font-face`、零外部 URL（离线桌面端纪律）

三个区域重新定义为**书脊 / 正文 / 边注**：左栏是编号账目行（当前项朱砂竖线），
中间是书眉 + 目录式账页，右栏是等宽时间的刻度边注。所有区块标题前统一一条
12px 朱砂短线，与 `ext/workspaces.css` 的 `.workspace-panel__title::before` 同款。

## 3. 行动清单重排（核心）

| 改前 | 改后 |
| --- | --- |
| 三张彩色圆角卡，纵向堆叠 | 三个**发丝线分栏**，共用一个账页 |
| 卡内再套白底圆角卡 | 一条记录 = 一行账目（`border-bottom` 发丝线） |
| 表头随内容滚走 | `.zone__head` 吸顶，计数用等宽数字 |
| 513 条已完成把整页撑长 | 每栏**独立滚动**，互不顶开 |
| 空态是虚线框 | 一行小字，不占高度 |

断点按真实窗口宽度分档，不靠猜测：

| 宽度 | 排布 |
| --- | --- |
| ≥1361px | 三列等宽账目栏（每列约 325px） |
| 1024–1360px | **两列**（待确认 / 进行中）+ 已完成跨两列的横带；三带各限高 190px |
| ≤1023px | 单列，保留手机底部弹层交互 |

1080px 是老板截图的窗口宽度：三列会把每列压到约 157px、标题折成 4 行，
所以这一档特意改成两列 + 跨行横带。

## 5. 实测（不是目测）

- 无头 Edge 直接渲染**真实 `index.html`**（不是静态 mock），三档宽度
  1080×768 / 1280×800 / 1440×900，外加 390px iframe 手机视图。
- `--dump-dom` 注入探针读 computed style，定位到白底圆角框来自
  `.app[data-frame][data-frame-layout="desktop"] .timeline`（四选择器，
  特异性高于普通覆盖规则）；据此补了同特异性覆盖，保证 headless 量到的
  就是用户看到的。
- 页面自带验证 rig 输出 `box=1078 scrollWidth=1078 horizontalScroll=false`，
  1080 档零横向溢出。
- 视觉验收发现并修掉：书眉标题被 nowrap 挤成两行、1080 下 chips 横向盖住
  右栏、横幅说明被 flex nowrap 挤成三行、压缩后桌面露出第二份导入面板、
  `[data-frame]` 规则把分区限高抬回 500px 导致已完成仍看不见。

## 7. 详情阅读面板（DETAIL-PANEL-1）

老板反馈「点击展开详情之后的展示区域可以变大，要不然看得很辛苦」。用 CDP 打开
真实页面（`1280×860` CSS 视口）点第一条「展开详情」，量到改动前：

| 指标 | 改前 | 改后 |
| --- | --- | --- |
| 详情内容高度 | 1004 px | 1178 px（字号与行距放大后） |
| 详情宽度 | 421 px | 1040 px |
| 详情可见高度 | **52 px** | **653 px** |
| 可见面积 | 约 2.2 万 px² | 约 67.9 万 px²（约 31 倍） |
| 所在分区 | `max-height: 190px` | 详情脱离分区，面板自带滚动 |

根因是 1024–1360px 断点把每个分区限高 190px，而详情有 18 行键值表加证据、
回滚、因果解释等装饰块，全部塞进这条窄栏里滚。

改法仍是纯 CSS 覆盖层，不动 `app.js` 的 DOM、不新增字典键、不新增脚本：

- `.app .card.is-expanded` 上声明 5 个 `--dp-*` 几何令牌（宽 `min(1040px, 92vw)`、
  高 `min(82vh, 780px)`、居中、标题栏 52px），子元素继承。
- `.card__detail` 改为 `position: fixed` 的居中阅读面板，内部 `overflow-y: auto`
  + `overscroll-behavior: contain`（滚动不穿透整页）。
- **关闭入口复用原按钮**：`.card__toggle` 一起固定在面板顶部作为标题栏，展开态
  它自带「收起详情」文案，点整条都会走原来的 `toggleCard()`，无需新 JS、新键，
  键盘 Enter/Space 也照旧可用。
- `.app:has(.card.is-expanded)::before` 压暗背景，`pointer-events: none` 保证
  背景里其它卡片仍可点；面板 `z-index` 88 / 标题栏 89，位于信任中心之上、
  toast（90）与 modal（95）之下。
- 键值表改成 `minmax(150px, 200px) 1fr` 两列、行距 1.7，展开卡片的 badges / meta
  不再在账目栏里留下一条无主的残影。

`tests/test_ledger_face.py` 新增 3 项守卫（共 15 项）：面板固定定位与尺寸令牌、
标题栏即收起条、遮罩与键值表排版。

## 8. 边界（如实申报）

- **纯覆盖层**：`styles.css` 负责所有断点与 aria 契约，`ledger.css` 只改外观；
  没有改 `app.js` 的 DOM，也没有第二套业务逻辑。
- 手机端内容仍在底部弹层里，需点进度球展开；未展开时的空白是原有交互，
  不是本次改动引入。
- 桌面隐藏了 sheet 内的导入面板副本，右侧 rail 那份保留，功能未减少。
- `capabilities` 仍为 `['web']`；安装包仍是自签名、根不受信任。
