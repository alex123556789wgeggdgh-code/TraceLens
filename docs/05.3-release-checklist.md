## 2. 签名的信任边界（必须让人看懂）

* 本清单里的签名一律是**自签名**：本机自己造一张证书给自己签。
  它只证明两件事：文件从那台机器的私钥出来、内容没被改过。
* 它**不是**受信任发布者签名。`Get-AuthenticodeSignature` 对自签名产物的
  预期状态是 `NotTrusted`（签名有效、证书链不受信任）；
  Windows SmartScreen、企业 AppLocker/WDAC 仍会拦。
* 要消除报警：买 OV/EV 代码签名证书，或把导出的 `TraceLens-SelfSigned.cer`
  导入 `本地计算机\受信任的人`（`LocalMachine\TrustedPublisher`，需管理员）。
  只在开发机上这么做，别当成"正式发布"。
* 默认**不加时间戳**：自签名 + 无时间戳 = 证书过期后签名验证会转为失效。
  有可信时间戳服务时给 `-TimestampServer http://timestamp.digicert.com`。
* 构建期不签名（`electron-builder.yml` 里没有任何签名选项配置，
  `forceCodeSigning: false`）：签名是构建之后的独立步骤
  （`tools/sign_and_hash.ps1`），失败就写失败，绝不为"看起来已签名"造假。

## 5. 与规格的偏差（明说）

1. 规格要求 PyInstaller **单文件** exe；本机单文件 exe 造得出来、跑不起来
   （引导阶段被沙箱拒绝），交付改为**单目录 onedir**，由 NSIS 安装包整体打包。
   代码两种布局都认（`desktop/sidecar.js` 依次找
   `resources/sidecar/agent-explainer-sidecar.exe` 与
   `resources/sidecar/agent-explainer-sidecar/agent-explainer-sidecar.exe`）。
   普通机器上 `python tools/build_sidecar.py --build`（不带 `--onedir`）就是单文件。
2. 规格隐含"pip 装 PyInstaller"；本机 pip 写临时目录被拒，脚本自动降级为
   标准库 wheel 下载解包（`--vendor`），产物等价。
3. 记录持久化是 4.9 已定口径（JSONL 追加日志 + 内存索引），本任务只验证，未改动。

## 7. 阻塞清单（按影响排序，全部可复现）

1. **命名管道被沙箱禁止 → Electron GUI 起不来**（影响最大：开发模式窗口、
   electron-builder 打包全被这一条卡住）。
   复现（Python 拉起，能抓到退出码与 stderr）：
   ```bash
   python -c "import subprocess;subprocess.run([r'desktop\node_modules\electron\dist\electron.exe','.','--selfcheck','--no-sandbox','--disable-crash-reporter','--disable-gpu'],cwd=r'desktop',capture_output=True)"
   # 退出码 4294930435（0xffff7003），stderr: crashpad_client_win.cc:867] not connected
   ```
   解锁条件：允许命名管道（去掉进程创建限制），或在非沙箱桌面会话里跑
   `npm start` / `npm run selfcheck`（预期打印
   `{"tracelens_desktop_selfcheck":{"ok":true,…}}` 且退出码 0）。
2. **npm 生命周期脚本 spawn 被拒（EPERM，根因同上：node 默认用管道接子进程输出）**
   → 完整 `npm install` 不完整。复现：`cd desktop; npm install`
   （`npm_config_cache` 指到工作区，避免用户缓存目录 EACCES）。
   绕过：`npm install --ignore-scripts` + 手工把 Electron zip 解到
   `desktop/node_modules/electron/dist/` 并写 `path.txt`（内容 `electron.exe`）。
3. **CertEnroll / 证书库 Access denied + .NET 造证书缺 EKU** → 签名未产出。
   复现：`tools/sign_and_hash.ps1`（脚本会把两条路的原始报错写进
   `SIGNATURE-STATUS.json` 的 `certificate.attempts`，并记 `unsigned=true`，
   产物状态 `NotSigned`）。
   解锁条件：允许 CertEnroll；或提供带 Code Signing EKU 的 PFX，
   用现成证书跑 `-SkipCertCreate` 路径。
4. **PyInstaller 单文件引导被沙箱拒绝** → 交付为 onedir（不影响产品行为）。
5. 本机是 Windows PowerShell 5.1（无 `pwsh`）：签名脚本的可复现调用形态是
   `& "$PSHOME\powershell.exe" -NoProfile -ExecutionPolicy Bypass -File tools\sign_and_hash.ps1`；
   脚本文件必须是 UTF-8 **带 BOM**，否则 5.1 把中文按 ANSI 解析成语法错误。

## 9. 5.3b（t26）复核：在"请求全权限"后重做打包的实测结论
