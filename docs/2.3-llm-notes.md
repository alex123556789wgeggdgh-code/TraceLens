# 2.3 LLM 增强版解释流水线 —— 选型、成本、评测与隐私说明

负责人：后端工程师 ｜ 前置：t4 [t2-2] 模板版解释流水线 ｜ 阶段：M2
被测实现：[explanations.py](../agent_explainer/explanations.py)、[prompts/explain_zh.md](../agent_explainer/prompts/explain_zh.md)、[prompts/explain_en.md](../agent_explainer/prompts/explain_en.md)
验收测试：[tests/test_explanation_llm.py](../tests/test_explanation_llm.py)（56 例，全部用 Mock 客户端，**不真实调用任何外部 API**）

> 一句话结论：LLM 是**可选外挂**，不是依赖。默认 `mode="template"`（架构 A7「LLM 非必需」+ K-12「无 key 全流程可用」）。
> 开启 LLM 后，模型只替换**一句话正文**；`l1 / l2 / l3` 恒为模板产物；文案要过 4 道上屏门禁，
> 任何失败（异常 / 超时 / 空 / 超长 / 泄漏隐私 / 假装已执行 / 要素不全）→ **整句回退模板**，界面永不空白。

## 1. 三闸 + 四门：什么时候真的调用模型

三道闸（全开才调用，任一关闭直接回退，连客户端都不问，省一次无谓开销）：

| 闸 | 判据 | 关闭时的回退原因码 |
| --- | --- | --- |
| ① 模式 | `ExplanationGenerator.mode == "llm"`（或单次 `generate(..., mode="llm")`） | `mode_template` |
| ② 设置中心 | 4.5 注入的 `settings.enabled == True` | `settings_disabled` |
| ③ 客户端 | 注入的客户端 `configured == True`（默认 `NullLLMClient` = False） | `client_not_configured` |

四道上屏门禁（顺序固定，任一失败 = 整句回退）：

| 门 | 规则 | 原因码 |
| --- | --- | --- |
| 长度 | 候选文案 ≤ `budget`（默认 120 字符） | `over_length` |
| 隐私 | 对**未脱敏原文**跑 lint（8 条，与产品 lint 同源） | `privacy:<label>` |
| 诚实 | 执行回执 ∉ {`executed`} 时禁出现「已完成/已执行/已删除/已发送/已支付/已写入…」等 | `overclaim:<词>` |
| 四要素 | 做了什么 / 因为 / 结果 / 你 —— 至少命中 3/4 | `incomplete` |

客户端层面的失败同样回退：`timeout`（`TimeoutError`）、`client_error:<类型>`、`client_returned_none`、
`client_returned_type:<类型>`、`empty`。全部原因写进 `explain()["llm"]["reason"]`，界面可直接显示「为什么回退了」。

**校验顺序刻意把隐私与假闭环放在脱敏之前**：模型把 `C:\Users\bob\…` 写进文案时，
不能靠「反正会被脱敏」蒙混上屏 —— 原文命中即拒收。

## 2. 出处（provenance）口径：为什么是 `hybrid` 而不是 `llm`

schema v1.1 的 `human_readable.generated_by ∈ template | llm | hybrid | human`，且 `llm/hybrid ⇒ may_contain_inference=true`（负向用例 N21 强制）。

- LLM 只重写"一句话正文"，`l1/l2/l3` 与三选项文案仍是模板渲染（可 lint、可重放、离线可用）；
- 因此 LLM 文案被采纳 → `generated_by="hybrid"`，并带 `model`、保留 `template_id`；
- 回退 → `generated_by="template"`、`model=null`、`may_contain_inference=false`；
- `render_human_readable(..., generated_by="auto")` 由生成器按当次调用结果自动判定（`enrich(records, generated_by="auto")` 同理）；
- 纯 `llm` 值预留给"整段文案都由模型产出"的未来形态（届时 `template_id=null`），本任务不产生该值。

**界面义务（t7）**：`may_contain_inference=true` 必须显示「AI 生成」标记 + 可展开的回退原因；
这是 K-14（信任度/控制感）与 K-08（不误导）的落地前提，不可省略。

## 3. 给下游的接口缝（t7 / t8 / t13 / t14 依赖这些名字）

```python
gen = make_generator(mode="llm",                 # 默认 "template"
                     llm_client=client,          # 注入；不注入 = NullLLMClient
                     settings={"enabled": True, "model": "qwen2.5:7b",
                               "base_url": "http://127.0.0.1:11434/v1",
                               "temperature": 0.2, "max_tokens": 260, "timeout_s": 8.0},
                     preferences={"audience": "A", "granularity": "L1",
                                  "verbosity": "standard", "plain_language": True,
                                  "focus": "progress", "language": None},
                     history=records[:6],         # 历史动作摘要（同会话最近 N 条）
                     prompt_dir=None)             # 覆盖提示词目录（评测/打包用）

gen.generate(record, "zh", mode=None, history=None) -> str     # 四要素单句 ≤120
gen.explain(record, "zh") -> {..., "generated_by", "llm"}      # 分字段 + 出处
gen.build_prompt(record, "zh") -> str                          # 提示词原文（评测脚本取这份）
gen.llm_status() -> {...}                                      # 设置页 / 审计：三闸状态
gen.render_human_readable(rec, "zh", generated_by="auto")      # 完整 human_readable
gen.enrich(records, generated_by="auto")                       # 批处理，返回新记录
gen.set_mode("llm") / set_preferences({...}) / set_history([...])   # 设置中心热更新
```

`explain()["llm"]` 的形状（t7 渲染 + 埋点都按这个）：
`{"mode", "used", "reason", "model", "prompt_chars", "chars", "language"}`。

传给客户端的关键字（t13 实现 OpenAI 兼容客户端时按此发送）：
`model, temperature, max_tokens, timeout_s, language, max_length, output_language,
record_id, facts_hash, history_count, prompt_template_id, response_format="plain_text", stop=["\n"]`。
约定：客户端自己尊重 `timeout_s`；抛 `TimeoutError` 即计为超时；**异常信息里绝不含密钥**。

## 4. 提示词工程

- **资源文件**：`agent_explainer/prompts/explain_zh.md` / `explain_en.md`（`{{token}}` 占位，`PROMPT_TEMPLATE_ID="explainer.prompt.v1"`）。
  文件缺失/为空 → 内置兜底提示词 + `stats["prompt_missing"]`，不崩（已测）。
  **打包注意**：PyInstaller 必须 `--add-data "agent_explainer/prompts;agent_explainer/prompts"`（t12 清单要点）。
- **双语原生**，不是翻译：中文模板用「决定 ≠ 生效」，英文模板用 "A decision is not an effect"。
  事实值原样透传（源数据里的中文值在英文提示词里仍是中文）—— 只有骨架与规则是英文，已测。
- **内容分层**：硬约束 9 条 → 用户与任务（任务名、助手名、受众画像、粒度、详略、白话、关注点、输出语言）
  → 本步事实人读摘要 → 历史动作摘要（默认最多 6 条，每条 ≤46 字符）
  → 已核对事实 JSON（`<!-- TRACELENS-FACTS-BEGIN/END -->` 包裹，**已脱敏**，含 `facts_hash` 与 `max_length`）。
- **自校准**：长度上限、输出语言、`execution_receipt.state` 都写进提示词，模型无需猜；
  事实里没有的字段要求写「来源没说明」，禁止补全动机。
- 偏好来源：设置中心显式设置 > 记录 `context`（`audience_profile / default_granularity / user_language`）> 内置默认；
  非法值白名单免疫（已测）。

## 5. 模型选型

| 方案 | 接入 | 中文口语质量 | 延迟（7B 级） | 单位成本 | 隐私 | 结论 |
| --- | --- | --- | --- | --- | --- | --- |
| **本地 Qwen2.5-7B-Instruct 4-bit**（Ollama / llama.cpp / vLLM） | OpenAI 兼容 `http://127.0.0.1:11434/v1` | 好，短句指令遵循稳 | 2–5 s/条（独显 ≥8GB） | 电费≈0 | 数据不出机器 | **MVP 默认推荐** |
| 本地 Phi-4 / Qwen2.5-3B | 同上 | 中（3B 偶发漏要素） | 1–3 s/条（CPU 可跑） | ≈0 | 数据不出机器 | 低端机降级档 |
| DeepSeek（deepseek-chat，OpenAI 兼容） | 云 | 好 | P50 1.5–4 s，P95 6–12 s | 见 §6 | 需出境，**显式 opt-in** | 云端首选 |
| GLM-4-Flash /  glm-4-air | 云 | 中–好 | P50 1–3 s | 低 | 同上 | 备选 |
| gpt-4o-mini / gpt-4o | 云 | 好 / 很好 | P50 1.5–4 s | 高于本地与国产档 | 同上 | 不做 MVP 默认 |

选型理由：本任务的语言约束极强（≤120 字、四要素、禁推测、禁假闭环），
**守规矩比"更聪明"更重要**；门禁已经把"更聪明"的收益压得很小，把"越界"的代价放大到 0。
7B 级本地模型足够，且同时满足 K-12（无 key/断网可用）与隐私默认（数据不出机器）。
不选 GPT-4 级：成本与出境风险都更高，易懂度提升无法用 K-05 证明（需 t11 实测背书）。

## 6. 成本与延迟估算（**假设，待 t11 实测回填**）

实测输入规模（本仓库 36 条夹具 × 中英各一次，Mock 客户端计数）：

| 指标 | 中文提示词 | 英文提示词 |
| --- | --- | --- |
| 字符 | 2463 – 2945（中位 2704） | 4157 – 4589（中位 4354） |
| token 估算 | 1176 – 1384（中位 1280） | 1056 – 1267（中位 1166） |
| 输出 | ≤120 字符（实测中位 84）≈ ≤150 token | 同 |

估算假设（写死在方案里，实测后以实测为准）：
token 估算比例 = 中文 1 字≈1 token、西文 4 字符≈1 token；每条记录 1 次调用（双语界面 2 次）；
历史摘要默认 6 条，关掉可省约 15% 输入；云价按公开挂牌价，**t11 前需按当期牌价复核**。

| 场景 | 单条 P50 | 单条 P95 | 50 条输入 token | 50 条输出 token | 云端费用估算 |
| --- | --- | --- | --- | --- | --- |
| 本地 7B 4-bit（≥8GB 独显） | 2–5 s | 6–10 s | ~64k | ~7.5k | ≈0（电费量级） |
| 本地 3B / CPU | 1–3 s | 4–8 s | 同上 | 同上 | ≈0 |
| 云 deepseek-chat | 1.5–4 s | 6–12 s | ~64k | ~7.5k | ≈¥0.15（输入 ¥1/M + 输出 ¥2/M 量级） |
| 云 gpt-4o-mini | 1.5–4 s | 6–12 s | ~64k | ~7.5k | ≈$0.02 |

产品含义：
1. **界面不能被 LLM 卡住** —— 模板句先出（毫秒级），LLM 句作为"增强版"异步替换；超时预算 8 s（`settings.timeout_s`）。
2. 50 条评测 = 几分钱、几分钟量级 → 成本不是否决项；**延迟与隐私才是**。
3. 若 t11 实测的 P95 > 12 s：把 `timeout_s` 降到 5 s、默认切本地 7B，并把"AI 增强"入口标注为「慢」。

## 7. 50 条样本人工评测方案（交给 t11 执行，口径由本任务锁定）

**样本集（50 条）**：36 条现有合成夹具（12 条 native + 8 条 langfuse + 7 条 otel_genai + 9 条 mcp_events，
全部 `synthetic/demo_data=true`）+ 14 条按夹具改写的边界变体（原因缺失、结果缺失、执行回执 unreported、
超长入参、count=0/1/999、置信度 ≤0.6、外部发送、不可逆删除、已过期、决定已记录但未执行、双语混排、工具报错、
成本缺失、粒度 L3）。**Q6 已裁决**：发起人不提供真实 trace，验收不依赖真实样本，也不再索要。

**评委**：3 名非技术用户（映射产品画像 A 急躁型 / B 谨慎型 / C 学习型各 1 人），
不看代码、不看界面说明，15 分钟一轮，共两轮（每轮 25 条）。

**方法**：同一条记录、同一渲染位置的**盲评配对**——模板句 vs LLM 句，顺序随机、不告知来源，
每句回答：
1. 「这句话我看懂了吗」1–5 分（K-05 同口径：≥4 记易懂）；
2. 复述测试：这句话里的动作**现在是什么状态**？需要我做什么？（复述正确 = 通过；复述出"已经执行了"= 误导）；
3. 二选一：更愿意相信哪句（模板 / LLM / 说不清）。

**判定线**：
- 通过：LLM 侧易懂率（≥4/5）**≥ 80%**（K-05 口径，按 3 人 × 50 条 = 150 次判定计），且配对里 LLM 不劣于模板；
- **红线**：LLM 侧「误导」判定数必须为 **0**（决定≠生效 / 不夸大能力）。出现 1 例即判不通过，回到门禁与提示词修；
- 复述正确率 ≥ 70%（K-05 第二口径）；
- 配对 150 次判定用 McNemar 检查两侧不一致格子的不对称（小样本只做方向性描述，**不写"统计显著"**）。

**记录表列**：`record_id | 语言 | 呈现顺序 | 来源(模板/LLM，解码后才看) | 易懂1-5 | 复述正确(Y/N) | 误导(Y/N) | 偏好 | 备注`
落 `docs/05-test-report.md`，首页标注「模拟数据，非真人测试」（A2）。

**不通过后的动作（A7 预案）**：模板易懂度 < 80% 才允许把 LLM 从 Should 提到 Must 并重估成本；
LLM 易懂度 < 80% 或出现误导 → 保持 `mode="template"` 默认，LLM 增强降级为实验开关。

## 8. 隐私与脱敏

1. **数据侧**：夹具与样本全部合成（A2），无真实人名/路径/金额/客户数据。
2. **进提示词的每个字符串**都过 `_redact()`（真实用户目录、密钥形态、令牌、长数字串 → `<path:1>` 等占位符）；
   工具入参摘要在适配器层就已脱敏。测试断言：36 条夹具的中英提示词对 6 条产品级隐私模式**零命中**。
3. **出屏侧**：`LLM_FORBIDDEN_PATTERNS` 8 条 = 产品 lint（[tools/validate_schema.py](../tools/validate_schema.py)）6 条**逐字同步** + 短密钥、邮箱两条加码；
   包内不能 `import tools/`，所以保留副本，由测试双向比对防漂移（清单漂移 = 测试失败）。
4. **密钥**：`LLMSettings` 只记 `api_key_present` 有无，`api_key/key/token` 的**值一律丢弃**；
   `base_url` 过脱敏；`repr()`、`to_public_dict()`、审计里都不出现密钥明文（架构 §12 明文禁令）。
   真实密钥归 t13：Windows DPAPI（`CryptProtectData`）或环境变量，绝不落配置文件明文。
5. **云端发送 = 显式 opt-in**：默认本地/关闭；设置页要写清"会把这一步的脱敏事实发给 <model>"。
   审计建议记 `model / prompt_template_id / prompt 长度 / facts_hash / 回退原因`，**不记提示词与文案正文**（提示词里已是脱敏事实，仍不必整份入库）。
6. **不出网保证**：`agent_explainer` 包零第三方依赖、零网络调用（AST 白名单 + 调用后 `sys.modules` 不新增网络栈，均已测）。
   出网只发生在 t13 注入的客户端里。

## 9. 可观测性（`gen.stats` → 指标埋点）

| 计数键 | 用途 |
| --- | --- |
| `llm_calls / llm_used / llm_fallback / llm_rejected` | 增强命中率、回退率（K-05 相关，回退率高 = 模型不守规矩） |
| `prompt_chars`（最近一次） | 成本与体积监控；提示词膨胀告警阈值建议 4000 |
| `prompt_missing` | 提示词资源缺失（打包漏 `--add-data` 的第一现场） |
| 原有 `generated / clipped / degraded_total / reason_missing / result_missing / needs_action / low_confidence` | 模板侧质量，t4 口径不变 |

建议 t14 摄取侧把 `explain()["llm"]["reason"]` 分布做成饼图：
`timeout` 多 → 换本地/降 timeout；`over_length / incomplete` 多 → 提示词或模型档位问题；
`overclaim / privacy` 任何非零都要当缺陷查（红线 0 容忍）。

## 11. 遗留与交接

- **t13**：实现 OpenAI 兼容客户端（`LLMClient` 协议 + DPAPI/环境变量取密钥 + 尊重 `timeout_s`）；本任务**没有**写任何真实 HTTP 客户端。
- **t11**：按 §7 执行 50 条盲评，回填 §6 的实测 P50/P95 与真实 token 计数（替换估算）。
- **t12**：PyInstaller `--add-data` 带上 `agent_explainer/prompts`（漏了会静默走内置兜底模板，`stats["prompt_missing"]` 可查）。
- 待观察：入参摘要很长时事实 JSON 逼近 `FACTS_JSON_LIMIT`（3600 字符）会按 `history → tool_params → suggested_next → uncertainty` 顺序瘦身；
  真实负载下若频繁触发，考虑把提示词压到 1k token 档（省 20% 输入）。
